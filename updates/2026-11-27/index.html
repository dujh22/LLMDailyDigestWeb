RepoFactory：低成本代理指标驱动环境进化

用合理性、实现范围和结构耦合度等即时指标，替代昂贵求解反馈，持续改进长程编程训练环境。

★ 3 子主题：环境演化 机器之心  EnvironmentEvolve

 环境演化 人工智能辅助编程 长程任务 数据合成 模型训练

代码：https://github.com/IQuestLab/RepoFactory
数据集：https://huggingface.co/datasets/IQuestLab/RepoFactory
原文：https://mp.weixin.qq.com/s/8BKmJDMmLslP67CrezrC9Q
用途

在长程代码智能体训练中直接使用其环境与数据，或借鉴合理性、实现范围和结构耦合度指标低成本筛选并迭代仓库任务。

启示

训练环境的价值可以由可即时计算的代码规模与结构信号近似衡量，从而无需频繁运行昂贵的智能体求解和下游训练也能获得可迁移的性能收益。

📄 详细内容
  • 问题：真实软件仓库虽适合构建长程编程任务，但现有流程只验证环境能否运行和打分，无法持续提升任务的训练价值。
  • 旧法为何失效：依赖智能体完整 rollout 或训练后的下游评测判断环境修改效果，对包含大量实现与调试的长程任务成本高、反馈慢。
  • 方法：RepoFactory 以参考实现满分、初始工作区零分保证合理性，再用实现范围 S 衡量工作量、用函数调用可达关系形成的结构耦合度 C 衡量组件协作；构造智能体据此联合修改参考实现、任务说明和测试，并循环执行验证与代码分析。
  • 实验：用进化环境微调 Qwen3.5-35B-A3B 后，NL2Repo-Bench 得分由 23.8 升至 46.4，五项编程评测平均提升 8.5 个百分点；相较未进化环境，额外提升分别为 5.1 和 2.1 个百分点。500 个候选仓库中的有效环境由 169 个增至 347 个，产出率从 33.8% 升至 69.4%。
  • 局限与后续：完整环境集含 10,159 个环境、覆盖 17 个软件领域，但目前主要面向 Python，首批仅发布 200 个尚未进化的环境及其 Docker 镜像。

★ 3 子主题：系统优化 量子位  SystemEvolve SwarmEvolve CodeEvolve ResearchEvolve

 多智能体系统 系统优化 人工智能辅助编程 执行验证 长程任务

原文：https://www.qbitai.com/2026/11/513053.html
用途

在数据库、搜索引擎或推理框架的持续性能优化中，借鉴角色分工、实验契约和隔离验证机制，自主发现瓶颈并交付可审查的代码改进。

启示

可靠的自主工程不取决于生成更多代码，而取决于将探索、合入决策和正确性验证分离，并让失败实验成为后续搜索的共享证据。

📄 详细内容
  • 问题：系统性能优化需要持续定位底层瓶颈、验证正确性并排除局部退化，难以依靠一次性代码生成完成。
  • 旧法为何失效：多个智能体直接改同一代码库容易重复或覆盖工作，也可能把随机波动、基准投机或未覆盖的语义错误误判为有效优化。
  • 方法：20个智能体分为调研员、指挥员和验证员，以实验契约约束性能、正确性、兼容性和内存使用，在隔离环境中持续提出、审查和验证优化假设，并共享失败经验。
  • 实验：4天完成约350次实验并保留6项优化；在ClickBench的1亿行、40条查询设置下，Quickwit总热查询耗时由40.5秒降至27.9秒，geomean由403毫秒降至304毫秒，较Duckflight公开成绩快16%，单项查询最高降87%。
  • 局限与后续：约350次实验仅6项通过审查；团队正继续优化SearchBench索引效率，并计划将系统用于更多基础设施软件。

Play2Evolve：趣味反馈驱动游戏演化

让智能体以趣味性反馈反复试玩、诊断并演化游戏，在GameCraft-Bench上取得60.05分。

★ 3 子主题：游戏生成 Hugging Face Papers  CodeEvolve AgentEvolve Evolve应用 TaskEvolve

 游戏生成 智能体 自演化 人工智能辅助编程 视频生成

论文：https://arxiv.org/abs/2611.33457
代码：https://github.com/showlab/Play2Evolve
用途

在自然语言游戏生成或代码智能体系统中，可借鉴其试玩—诊断—修改闭环，持续优化功能、视觉素材与玩法设计。

启示

游戏可执行性并不等于可玩性，而将趣味性拆成可诊断维度后，它可以成为智能体持续演化软件产品的有效反馈信号。

📄 详细内容
  • 问题：代码智能体虽能根据自然语言生成可运行游戏，但难以同时保证功能可靠、视觉吸引力和支持探索与成长的丰富玩法。
  • 旧法为何失效：已有方法主要关注游戏能否运行，缺少对实际游玩体验的持续反馈，无法系统发现玩法、画面和功能层面的问题。
  • 方法：Play2Evolve采用初始化、精炼和演化三阶段递归开发流程，让智能体试玩游戏并从功能、视觉和玩法三个维度诊断问题，再据此修复缺陷、改进素材并提出新的玩法与美学目标；同时结合视频生成模型与代码制作静态和动态资产。
  • 实验：在GameCraft-Bench上取得60.05分，高于仅初始化的50.81和Play2Code的52.46；人类总体质量评分达到3.67，对照方法分别为2.38和2.43。

PyRUA-Dex：编程智能体生成双手策略

用编程智能体自主探索、组合并精炼操作程序，摆脱灵巧双手训练对高质量示范数据的依赖。

★ 3 子主题：具身规划 Hugging Face Papers  RobotEvolve

 具身智能 智能体 任务规划 多智能体系统 技能生成

论文：https://arxiv.org/abs/2611.33144
用途

在缺少机器人示范数据的双手灵巧操作系统中，可借鉴其多智能体技能探索、程序蒸馏与随机化精炼机制来生成可执行策略。

启示

灵巧操作不必完全依赖动作示范，将技能表示为可组合、可调试的程序，能让智能体通过试错直接获得复杂且可迁移的控制能力。

📄 详细内容
  • 问题：灵巧双手操作缺少高质量示范，限制了复杂操作策略的学习与真实机器人应用。
  • 旧法为何失效：人体视频重定向不精确，遥操作缺乏力反馈，外骨骼采集又难以规模化。
  • 方法：PyRUA-Dex 先让多个编程智能体并行探索任务技能及其组合方式，再由蒸馏智能体将成功尝试压缩为任务库和单一程序；随后利用随机化布局提升程序的鲁棒性与执行效率。
  • 实验：仿真中在 Bench2Dex 获得 72.9 分，在完全随机化的 DexJoCo 上达到 81.0% 成功率，均超过所有对比训练策略；在两只22自由度灵巧手组成的真实平台上完成钢琴、书法等任务，从乐谱学习新曲目最快仅需30分钟。

Real2SimLab：真实到仿真统一评测

用统一的程序执行接口和原生评分器，解决真实到仿真方法跨基准评测需重复适配的问题。

★ 2 子主题：智能体评测 Hugging Face Papers  PhysicalEvolve EvalEvolve InfraEvolve HarnessEvolve

 智能体评估 模型评估 具身智能 数据合成 人工智能辅助编程

论文：https://arxiv.org/abs/2611.34849
用途

在视频到仿真系统中，将其作为统一评测与奖励标注基础设施，接入不同编程智能体和既有基准。

启示

以可执行仿真程序作为方法与基准之间的统一契约，可将跨基准适配从两两集成转化为平台级复用，同时保持原始评分标准。

📄 详细内容
  • 问题：真实到仿真方法可从视频生成仿真程序，但不同基准的输入、交付物和评分流程各异，评测 N 个方法与 M 个基准需要 N×M 次集成。
  • 旧法为何失效：各基准采用独立接口和流水线，方法开发者必须逐一适配，难以公平扩展评测并复用训练数据生产流程。
  • 方法：Real2SimLab 统一运行方法生成的程序，并调用各基准原有评分器评价仿真结果；同时提供训练数据与奖励标注流水线，通过过滤基准已有视频避免数据污染。
  • 实验：平台目前支持 47 个编程智能体、5 个非智能体方法和6个真实到仿真基准，并开源收录近300篇相关论文的 Awesome-Real2Sim 研究图谱。

EgoUseBench：动态第一人称任务评测

用持续更新的第一人称观察评测计算机操作智能体，在线场景成功率较明确指令场景低26.3%。

 智能体评估 第一人称视觉 图形用户界面智能体 连续交互 真实世界任务

论文：https://arxiv.org/abs/2611.34466
用途

在智能眼镜或桌面操作智能体中将其作为评测基准，测试系统能否依据持续到来的第一人称观察修正任务理解和执行动作。

启示

计算机操作智能体的关键瓶颈不只是看懂当前环境，而是在证据和意图变化后持续判断先前动作是否仍然有效。

📄 详细内容
  • 问题：智能眼镜让计算机任务与用户所处的真实环境相连，但视角受限、证据不完整且意图持续变化，智能体必须及时修正理解与既有操作。
  • 旧法为何失效：传统计算机操作评测主要依赖明确指令或执行前给定的静态上下文，无法检验智能体能否持续跟随新的观察和需求变化。
  • 方法：EgoUseBench设置Computer-Use、Offline Ego Use和Online Ego Use三种交互场景，并分别追踪第一人称观察、用户需求与网站状态；任务变化分为需求修订的Graft、新观察到达的Refresh和智能体主动求证的Clarify。
  • 实验：基于超过74小时的真实第一人称录像构建693个任务；先进模型在Online Ego Use中的平均成功率比Computer-Use低26.3%。

VibeVideoAgent：多时钟闭环感知

用隔离的短时多模态检查和多时钟证据反馈，解决代码视频运行无错却存在画面缺陷与音画不同步的问题。

★ 2 子主题：视频生成 Hugging Face Papers  NewApply TaskEvolve

 视频生成 智能体 多模态 执行反馈 长程任务

论文：https://arxiv.org/abs/2611.34237
用途

在代码驱动的视频制作智能体中接入其短时感知、紧凑证据反馈和最小预览协议，用于在完整渲染前发现画面与音画同步缺陷。

启示

代码执行正确性无法覆盖感知正确性，长程生成中的有效反馈应当早期、局部、证据化并与不同媒体时钟对齐。

📄 详细内容
  • 问题：代码驱动的视频生成虽能精确控制排版、可视化、音频和多镜头场景，但程序正常退出并不代表成片在画面、交互和音画同步上正确。
  • 旧法为何失效：把渲染帧和音频持续送回编码上下文会挤占长程任务空间；只检查最终全分辨率成片，又会让早期设计错误演变为昂贵返工。
  • 方法：VibeVideoAgent以无需训练的框架将多模态感知放入独立短时上下文，只向编码智能体返回紧凑且有证据依据的 Findings；七种原语基于统一多时钟表征执行由粗到细检查、跨模态需求验证、版本对比和局部信号测量，并先用最小预览测试高风险决策。
  • 实验：在239项VibeVideoBench任务、智能体运行时间匹配且感知模型固定的设置下，Claude Opus 5.5的整体视听质量由4.03升至4.43，GPT-6 Astra由4.03升至4.27，Claude Sonnet 5.5由3.97升至4.10；音画同步最高提升0.56，消融实验显示各组件均有贡献。

用跨深度与循环选择性复用KV记忆，缓解循环Transformer表达力提升伴随的效率损失，最高实现1.7倍词元效率。

用途

在高效语言模型预训练或继续预训练中直接采用MoLT代码，利用KV循环记忆减少重复层遍历并兼顾模型质量与推理延迟。

启示

循环模型不必传递完整残差状态；将KV视为可选择读取的跨循环记忆，可以解除同位置串行依赖，使表达能力与计算效率不再必然冲突。

📄 详细内容
  • 问题：循环Transformer通过跨循环共享层增强表达能力，但多次遍历会降低训练与推理效率，需要重新设计循环间传递的信息。
  • 旧法为何失效：传统循环架构依赖残差流和同位置的跨循环状态，导致循环必须串行执行，限制并行训练及超出训练循环数的解码。
  • 方法：MoLT以KV作为跨深度和循环的记忆；MoLT-R保留残差流并读取局部KV，MoLT-KV则从嵌入重启，结合当前循环局部KV与前序循环历史位置KV。U-MoLT进一步分离记忆构建和预测读出，跳过不影响预测的解码器遍历。
  • 实验：在4000亿词元预训练中，U-MoLT在700M、1.5B稠密模型及3B MoE模型上优于OLMo3；700M模型验证交叉熵词元效率提升1.7倍，3B MoE的10领域困惑度降低0.75、10任务准确率提高2.1个百分点。对Qwen3.5-0.8B-Base继续预训练1000亿词元后，11个领域交叉熵均下降，平均词元效率提升1.4倍；约113M参数设置下推理延迟与非循环OLMo3相当。
