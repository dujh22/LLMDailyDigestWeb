FreeToken 是 UC Berkeley、MIT 等机构联合推出的开源边缘端 MoE 推理系统，可让 RTX 4060 运行 Qwen3.6-35B，并让 RTX 5090 配合约 192GB 内存运行 284B 参数的 DeepSeek-V4-Flash。系统利用全层双缓冲，在 GPU 计算当前层时通过 PCIe 预取下一层专家权重，并根据实时总线带宽和 CPU 算力动态分配专家计算。其 Token 边界检查点与状态复用机制面向 Coding Agent 的上下文追加场景，可使后续多轮交互的首 Token 延迟降低 65%—80%。当显存被其他程序占用时，系统还能在线缩减 GPU 专家缓存、将计算转移至 CPU，实现不中断的弹性降级。

用途与启示
  • 降低超大规模 MoE 模型本地部署的 GPU 显存与数据中心基础设施门槛。
  • 为 Agent 的多轮工具调用和长上下文编辑提供低成本增量 Prefill 方案。
  • 展示将 CPU、内存、PCIe 与 GPU 统一调度，可显著改善权重卸载的吞吐和首 Token 延迟。
  • 为个人工作站上的私有化 AI 编程、研究代理和离线推理应用提供工程基础。

Google 提出 EnvHarness：环境自进化驱动 Agent 协同进化

EnvHarness 通过可编程环境脚手架与自动化 EnvRigger，根据智能体轨迹持续改造训练环境，在 SWE-bench Verified 上推动 Agent 成功率由 47.67% 提升至 54.79%。

子主题：环境共演 青稞AI  HarnessEvolve

 环境演化 协同演化 脚手架 智能体 自进化 SWE 软件工程

论文：https://arxiv.org/abs/2608.19880
代码：https://github.com/google-research/envharness
原文：https://mp.weixin.qq.com/s/edTpBcYqaJfnvVkGGxMScg

EnvHarness 无需修改环境底层实现，通过“开局（Stage）”“法则（Contract）”和“串联（Chain）”三类组件调整初始状态、交互规则及任务组合方式。EnvRigger 根据 Agent 的成功与失败轨迹执行观察、诊断、编写和验证四步闭环，自动生成针对能力短板或作弊捷径的环境脚手架。该机制让环境随 Agent 能力动态增加难度，形成环境与智能体的螺旋式协同进化。在 SWE-bench Verified 长线实验中，Agent 成功率从 47.67% 提升至 54.79%，且环境数量增加到 300 个时仍保持增长趋势。

用途与启示
  • 将环境由固定评测容器转化为可自动迭代的训练对象，为 Agent 自进化提供持续且针对性的课程。
  • 可利用轨迹诊断 Agent 的循环、超时、错误调用及捷径利用问题，并自动构造相应挑战。
  • Stage、Contract 与 Chain 为不侵入底层环境的动态改造提供了模块化接口，适合软件工程 Agent 的规模化训练。
  • 后续可扩展到视觉、GUI、具身及多智能体环境，并通过语义化任务组合构建更真实的长程挑战。

AI4AI-Bench：评测智能体能否设计更好的 AI 算法

Einsia AI 发布 AI4AI-Bench，以十个真实研究仓库和独立重跑机制评测 LLM Agent 能否超越调参与工程优化，真正修改学习算法并推动递归自我改进。

子主题：算法评测 机器之心  Awesome-RSI

 算法设计 科研基准 自我改进 AI编程 智能体 推理预算 实验执行 算法自研

论文：https://arxiv.org/abs/2608.20318
代码：https://github.com/Einsia/AI4AI-Bench
原文：https://mp.weixin.qq.com/s/cpVXuDEOEmlcT4jrlVh-IA

AI4AI-Bench 选取十个真实 AI 研究仓库，要求 Agent 在 4 小时内探索和修改源码，再于全新环境中独立重跑最长 12 小时，以冻结的隐藏评估器检验其算法是否优于原始基线。评测覆盖 29 种“模型、Agent 框架与推理强度”配置，共进行 290 组实验，Claude Opus 5 整体表现最佳，但最高推理档平均分仍只有 0.196，距离理论最优很远。263 份可分类提交中，141 份只调整训练运行方式，122 份真正修改损失函数、监督信号或更新规则；后者平均分为 0.226，显著高于前者的 0.126。随着 reasoning effort 提升，触及算法层的提交比例由 8% 增至 64%，实验次数、代码改动量和最终成绩也同步增长。优秀案例包括将一次性剪枝改造成蒸馏训练流程、把权重平均转化为可搜索优化问题，以及用求解器监督、模仿学习和 DAgger 改进 Agentic RL。

用途与启示
  • 为递归自我改进研究提供比代码修复更严格的算法设计能力评测框架。
  • 提示评测应将探索环境与最终验收隔离，并采用相同算力、数据和时间预算进行独立复现。
  • 说明增加推理预算的主要价值之一，是促使 Agent 从外围调参转向机制诊断、实验验证与算法修改。
  • 可用于研究如何让智能体的算法创新能力从偶发成功转变为稳定、可复现的科研流程。
