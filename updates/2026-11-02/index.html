HarnessEvolve：基于参考轨迹的可靠智能体自我进化

华为提出 HarnessEvolve，通过参考轨迹定位失败执行的首个偏离点，并以质量门和性能门筛除泄漏、提示膨胀及能力退化，实现更可靠且可跨框架迁移的智能体脚手架进化。

★ 3 子主题：脚手架演化 Tau Lab  HarnessEvolve SystemEvolve

 智能体脚手架演化 自演化 信用分配 轨迹验证 人工智能可靠性

原文：https://mp.weixin.qq.com/s/SkLbz6yhOSI3Rxeas4RF_Q?scene=1

HarnessEvolve 将智能体的执行、评估、优化和门控拆分为独立模块，并使用经过验证的参考轨迹与失败轨迹对齐，寻找首个动作偏离点。系统对错误原因进行聚类，据此生成提示、技能、工具或执行逻辑的候选修改，再通过质量门防止数据泄漏与提示膨胀，通过性能门抑制灾难性遗忘。该框架在 CloudCoreNetwork-QA、Wireless-QA、SearchQA、OfficeQA 和 SpreadsheetBench 上均超过 Base、GEPA、ACE 与 SkillOpt，并表现出跨智能体框架迁移能力。消融实验中移除参考轨迹比较后，CloudCoreNetwork-QA 准确率由 86.9% 降至 57.8%，表明细粒度首错诊断是主要性能来源。

用途与启示
  • 为长链智能体任务提供比终局成败信号更细粒度的信用分配机制，可用于定位工具调用或决策链中的首个错误。
  • 将候选修改生成与更新验收解耦，为智能体脚手架持续进化提供可审计的质量控制和回归保护。
  • 参考轨迹、错误聚类与快照池机制可复用于企业问答、开放域搜索、办公自动化和表格操作等工具型智能体。
  • 实际部署仍需关注参考轨迹真实性、评估智能体误判以及门控阈值对最终效果的影响。

DeepSeek提出下一代 Super-agent Harness 架构

DeepSeek提出面向持续在线、多任务并发与跨信道协作的 Super-agent 架构，以 Router-Worker 双层设计、事件驱动机制和运行时自愈突破单会话 Agent 的限制。

★ 3 子主题：智能体框架 DeepSeek  HarnessEvolve

 智能体执行框架 智能体运行时 状态持久化 长程智能体 系统优化

原文：https://mp.weixin.qq.com/s/SuHla75ppkRi6uow-lnWFg

DeepSeek将 Super-agent 定义为可跨会话保持上下文、并行推进多项任务，并具备连续、高效、主动和持久特征的 Agent 系统。架构采用常驻 Router 与隔离 Worker 的双层设计：Router 统一处理交互、全局记忆和任务分派，Worker 则携带完整工具并发执行具体任务。系统以群聊消息、邮件、代码评审和 CI 结果等 Trigger 驱动，通过程序 Fast Path 与语义 Slow Path 完成事件过滤和路由。计算、状态与环境相互分离，并结合 Watchdog 和异常恢复机制，使 Agent 能跨设备长期在线并持续接入真实工作环境。该方案强调 Session 应成为底层实现细节，而非用户管理多任务时的认知负担。

用途与启示
  • 为持续在线的个人助手、Coding Agent 和企业数字员工提供可扩展的运行时架构参考。
  • 通过 Router-Worker 分层兼顾全局上下文连续性与多任务并发吞吐量。
  • 利用事件过滤、订阅和直通路由减少无效模型调用，降低响应延迟与算力成本。
  • 将计算、状态和执行环境解耦，并引入 Watchdog，为长程任务的异常自愈与状态持久化提供工程路径。
  • 启示 Agent 产品应淡化 Session，让用户通过 IM、GitHub 等原有工作界面连续协作。

  • 可用于构建能够随任务和经验持续调整记忆机制的长程智能体。

Self-Evolving Rubrics：自进化准则驱动强化学习

文章汇总 SERPO、DynamicRubric、ARCO、EvoRubrics 与 EvoRubric，展示动态自进化准则如何为开放式生成和多步智能体训练持续提供细粒度奖励信号。

★ 3 子主题：奖励机制设计 小红书  EvolveLLM AgentTrainEvolve

 强化学习 奖励建模 自演化 策略优化 智能体

原文：https://www.xiaohongshu.com/discovery/item/6adf6637000000001802a617?source=webshare&xhsshare=pc_web&xsec_token=CBQR6syo1lSkiJHFKoOf4Zrz9NgNPQYu8CP9EtjpS7sz8=&xsec_source=pc_share
  • SERPO 构建“证据—准则—策略”闭环，通过输出分档、自动提炼判别准则及判定 Token 概率奖励，实现开放式任务的测试时策略优化。
  • DynamicRubric 让评估器与策略协同进化，以动态加权二元准则缓解策略增强后样本趋同和奖励分差塌陷。
  • ARCO 面向多步智能体轨迹，采用单模型双头架构逐步生成准则与步级奖励，使监督标准随智能体行为在线更新。

  • 这些工作共同尝试摆脱人工静态准则、外部奖励模型和密集标注，为开放式生成提供可持续演化的监督信号。
用途与启示
  • 可用于构建开放式任务的在线奖励机制，减少对标准答案和外部奖励模型的依赖。
  • 为多步智能体训练提供步级、细粒度且随策略变化自适应的过程监督。
  • 设计动态准则时应同步监测奖励塌陷、奖励饱和和奖励作弊，并加入一致性约束或对抗更新机制。
  • 轻量评估器与动态准则结合，有望降低强化学习训练和测试时优化的计算成本。

LobeHub 的 Super-agent 组织协作实验

LobeHub 通过分层智能体、持久化运行时、跨项目自动交接与 Acceptance 自动验收，探索从团队成员向自治、自演进组织升级的 Agentic 协作模式。

★ 2 子主题：多智能体协作框架 未知  SwarmEvolve SystemEvolve

 多智能体系统 多智能体协作 智能体编排 执行验证 长程任务

原文：https://mp.weixin.qq.com/s/QVu2luIrRTtNvsH-U65A8g

LobeHub 将组织中的智能体分为 Personal Agent、项目主管 Agent 和执行 Agent 三层，分别承担信息过滤、派活验收以及代码与设计等具体工作。其运行时将智能体循环、会话状态和执行环境解耦，利用队列与 Redis 推进长程任务，并把工具调用发送至 AWS 沙箱、Mac mini 或用户电脑执行。项目主管 Agent 可跨项目直接提出需求、触发开发和自动发版，从而减少人工转述造成的交接成本；开源工具 Acceptance 则通过截图、录屏和日志形成可审查的自动验收报告。团队还将失败反馈与 Agent Vent 聚类为任务并持续优化 harness，在 FrontierHarness 上取得 70% 通过率和 1.68 美元的单任务成本中位数。

用途与启示
  • 为企业设计 Agentic 组织提供三层角色划分，避免所有任务集中经过单一 Router，并降低信息干扰与人工微操。
  • 通过解耦状态、循环和执行环境，为常驻智能体及长程任务提供可恢复、可迁移的运行基础设施。
  • 将自动验收、人工打回和标准沉淀组成闭环，使人的职责逐步从执行转向审核、方向设定与责任承担。
  • 以跨智能体交接和持续优化 harness 为路径，推动团队从 L3 智能体成员向 L4 自治业务单元及 L5 自演进组织演进。

Falcon快速权重注意力实现持续学习

Falcon系列将递归快速权重记忆视为在线学习过程，通过前缀对齐和归一化更新兼顾语言建模、持续学习与长度外推能力。

★ 2 子主题：持续学习 arXiv  MemoryEvolve CacheEvolve GeneralizeEvolve NewModel

 持续学习 智能体记忆 模型训练 长上下文 系统优化

论文：https://arxiv.org/abs/2608.27763
原文：https://mp.weixin.qq.com/s/pQe3u8B6k0gI0Xsa09N78Q

论文在写后读自回归语义下，将局部快速记忆样本定义为前缀对齐对 (φ(k_{t-1}), v_t)，指出常见的同时间步关联虽然满足因果性，但优化的是不同内部目标。作者分别针对平方误差回归和负内积目标推导归一化一阶更新，并提出标量 NLMS 更新的 Falcon-1、按列扩展的 Falcon-2及滑动窗口小批次更新的 Falcon-3。该框架支持递归、掩码并行和分块并行实现，并通过正衰减重归一化改善数值稳定性。代表性变体在语言建模中保持竞争力，在可变位加法任务中提升长度外推表现，同时解耦时间对齐、可塑性、遗忘和有界排练四项特性。

用途与启示
  • 为固定大小递归状态提供可解释的在线学习规则，可用于构建具备持续适应能力的序列模型。
  • 前缀对齐分析表明，快速权重更新中的时间索引会直接改变内部优化目标，设计递归记忆时需明确读写顺序。
  • Falcon系列将可塑性、遗忘与有界排练模块化，便于针对长期记忆和灾难性遗忘开展独立调节与消融。
  • 分块并行实现为快速权重记忆兼顾训练吞吐量和长序列泛化提供了工程路径。

Claude Code修改系统提示词，限制复刻现有游戏

Anthropic通过修改Claude Code系统提示词限制复刻现有游戏，但该措施被质疑容易绕过且可能误拒原创开发需求。

★ 2 子主题：人工智能辅助编程 量子位  LogicEvolve HarnessEvolve

 人工智能辅助编程 安全对齐 SWE 软件工程 人工智能安全治理 人工智能可靠性

原文：https://mp.weixin.qq.com/s/ITPYABlfGBaOxGV_hsnD6Q

Anthropic确认在Claude Code所用模型的系统提示词中加入规则，允许原创游戏与通用类型开发，但拒绝重新创建属于他人的特定游戏。文章认为，开发者仍可通过任务拆分、名称替换或切换其他模型绕过限制，因此单一模型的提示词约束难以有效遏制游戏克隆。与此同时，该规则可能把常见游戏机制、原创项目或合法修改误判为侵权复刻，造成正常开发任务被拒绝。生成式编程显著降低了逆向工程、移植和游戏复刻的成本，也由此加剧游戏行业特别是独立开发者面临的知识产权风险。

用途与启示
