Firefly 将传统“先出题、后求解”的前向合成流程反转为 Back-Chaining：先让强模型在真实 MCP Server 上执行和探索工具调用，再依据实际输出生成任务及结构化答案。系统从约 3,000 个 MCP Server 中筛选出 240 个服务器和 993 个工具，构建 Tool Graph，并通过 DAG Exploration 采集包含串联、分支与汇合结构的真实、可达多工具调用轨迹。任务经过可验证性、明确性、可解释性、真实性和难度校准等自动质量检查，最终形成 5,144 个可验证任务。针对 API 返回变化、服务下线和限流等环境漂移问题，Firefly 基于缓存的真实调用结果构建 Retrieval-Augmented Tool-Call Simulator，使强化学习训练与评估能够离线复现。

  • 为 Tool-Calling Agent 提供兼顾规模、真实性与可验证性的强化学习训练数据生成方案。
  • 将 ground truth 正确性转化为数据生成流程的构造性质，减少对事后过滤和人工核验的依赖。
  • 通过 Tool Graph 与 DAG Exploration 提升异构工具空间的探索效率，扩展跨服务器、多工具组合任务的覆盖范围。
  • 利用真实调用缓存和检索增强模拟器缓解 API 环境漂移、服务不可用与调用限流，为可复现的智能体训练和评估提供基础设施。

研究揭示智能体脚手架演化的基准分数提升并不等同于可靠、高效且可迁移的真实改进，并提出基于保留感知审计的 EvoAudit 框架。

 智能体脚手架演化 模型评估 人工智能可靠性 递归自我改进 成本优化 跨域泛化

论文：https://arxiv.org/abs/2611.07624

研究通过重复评估、受控智能体扩展、组件干预和准入回放，审计四种脚手架演化方法在通用任务与编程任务上的表现。全部 16 个演化智能体都在覆盖新任务的同时丢失了原先能够完成的任务，说明聚合分数提升可能掩盖能力回退与运行稳定性问题。可靠性提升通常伴随更高部署成本，具体组件修改往往优于通用提醒，但不同修改组合后的收益可能失效或反转。最高分智能体在四个候选池中均未取得最大平均改进，严格准入规则还可能淘汰有价值的替代方案，而迁移收益取决于任务与脚手架类型。基于这些发现，EvoAudit 对选择、分析、变异和门控流程进行保留感知修订，并取得最佳整体表现。

用途与启示
  • 评估智能体演化时应同时追踪新增覆盖、既有能力退化和重复运行稳定性，而不能只比较聚合基准分数。
  • 将可靠性增益与部署成本联合报告，避免把显著增加推理开销换来的有限改进误判为高效演化。
