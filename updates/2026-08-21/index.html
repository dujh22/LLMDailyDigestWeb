代码：https://github.com/openJiuwen-ai/jiuwenswarm/tree/develop/jiuwenbox
原文：https://mp.weixin.qq.com/s/ACQ7ff-Vj0hGC3QLNHXsbg

WorkSwarm 将办公 Agent 组织成可拆解任务、分工执行的协作团队，具体命令、代码和文件操作则交由 JiuwenBox 隔离运行。JiuwenBox 采用接入层、管理平面和运行时三层架构，提供生命周期管理、策略引擎、接口认证及全程审计。系统支持 Linux 任务级沙箱、Windows 沙箱和开发中的微虚机沙箱，并可限制身份、文件路径、系统调用、网络与计算资源。用户可通过 /sandbox 命令或配置文件启用沙箱、设置命令例外和可写目录，第三方开发者也可借助统一 API 与 CLI 独立接入。

用途与启示
  • 为可操作本机文件、网络和命令的 Agent 建立默认隔离边界，降低越权、提权及破坏宿主系统的风险。
  • 通过任务级临时环境、最小权限和执行后销毁机制，为多智能体并发工作提供安全基础设施。
  • 策略配置、接口认证与审计日志适合企业内网、多租户以及金融、政务等高安全场景。
  • 统一 API 和零代码改造接入方式，可作为其他 Agent 框架设计安全执行层的参考。

LLM-as-a-Verifier：自验证让 DeepSeek V4 Flash 低成本反超闭源模型

LLM-as-a-Verifier 通过多轨迹采样、连续概率评分和高效排序，在无需微调或额外奖励模型的情况下，将 DeepSeek V4 Flash 在 Terminal-Bench 2.1 上的成功率从 78.7%提升至 88.0%。

子主题：自验证 AI前线  Groom

 自验证 测试时 候选选择 智能体 前缀缓存 成本优化 强化学习 验证扩展 连续评分 概率排序

论文：https://arxiv.org/abs/2607.05391
原文：https://mp.weixin.qq.com/s/kMGgCYnWBR78FhtuAD3g8g
  • 框架让同一 LLM 同时充当轨迹生成器和验证器，对 Agent 的完整执行过程进行细粒度评分与排序，无需训练专用 Reward Model。
  • DeepSeek V4 Flash 在 Terminal-Bench 2.1 上由单次生成的 78.7%提升至 Best-of-3 的 86.5%和 Best-of-5 的 88.0%，而候选池的 Oracle 上限达到 96.6%。
  • 方法利用评分 Token 的 logprob 计算连续验证分数，并沿评分粒度、重复验证和多评价准则三个方向扩展验证计算，缓解离散评分高平局率问题。
  • Probabilistic Pivot Tournament 减少候选间两两比较，前缀缓存降低长轨迹重复输入开销；包含生成与验证在内的单任务成本约为 0.11 美元。
用途与启示
  • 说明测试时扩展不仅可以增加候选生成量，还可将更多计算预算投入验证与选择环节。
  • 为开源或低价模型提供“多次尝试后自筛选”的性价比路径，模型选型应比较单位成功任务的总成本，而非只看 Token 单价。
  • 连续验证分数可作为进度跟踪和强化学习的高密度奖励信号，缓解复杂 Agent 缺少可靠奖励的问题。
  • Verifier 可被集成进 Agent Harness，成为运行时轨迹筛选、质量控制和故障恢复的基础组件。

AI 后训练缺失什么：智能体缺乏执行中的策略重估

实证研究发现，当前 LLM 智能体虽能端到端执行后训练，却会过早锁定初始方案，缺乏根据实验结果主动重估高层策略的机制。

子主题：策略重估 arXiv  EvolveLRM

 后训练 策略重估 智能体 执行反馈 自我改进

论文：https://arxiv.org/abs/2608.19072
原文：https://h5.lingowhale.com/s/Sjwo4Dj

研究区分了两类能力：在既定训练策略内迭代的执行级能力，以及随实验积累重新判断训练方向的策略级能力。对大量公开后训练轨迹的分析显示，智能体通常在任务初期便锁定策略，随后只进行局部参数或流程调整。经验驱动脚手架显著提升了执行表现，在 GSM8K 和 HumanEval 上分别提高 12.6 与 40.8 分，但未促使策略发生变化。人工指导可以改变初始方向，增加推理算力也对较简单任务有效，但智能体进入训练后仍会回到局部调整循环，说明核心缺口是执行期间的自主策略重估机制。

用途与启示
  • 评估自动后训练系统时，应将“执行优化能力”与“策略重估能力”分开测量，避免用最终性能掩盖策略僵化。
  • 可在训练闭环中加入变点检测、反事实实验和策略级停止条件，强制智能体根据新证据重新审视方案。
  • 仅增加经验库、人工提示或推理预算不足以实现真正的递归改进，研究重点应转向训中反思与高层决策更新机制。
  • 可用于设计更能衡量 AI-for-AI 自主研发能力的长程后训练基准与轨迹分析指标。

Chain-of-Experience 通过在测试时积累自反馈与环境反馈形成持续改进闭环，在数学、编程和知识任务上同时提升准确率与成本效率。

子主题：经验学习 Hugging Face Papers  EvolveLLM

论文：https://arxiv.org/abs/2608.18027

论文提出 Chain-of-Experience（CoE），让 LLM 在推理阶段通过与自身或环境反复交互，积累经验轨迹并持续改进。研究覆盖数学、编程和知识任务，并测试 GPT-5、Gemini-2.5 Pro、Claude-4.5 Sonnet 等 8 个模型。仅使用模型自反馈即可带来显著收益，综合来看准确率提升 5.6%，API 成本降低 19%，且单位 token 的准确率优于现有测试时策略。模型反馈与正确性、公开测试通过率等环境信号具有互补性，多数增益出现在迭代早期；基础能力更强的模型通常也具有更高的经验改进能力，并能较好抵御弱反馈或伪反馈。

用途与启示
  • 为无需更新参数的测试时持续学习提供统一范式，可将历史交互轨迹转化为后续推理经验。
  • 在智能体和代码生成系统中组合自反馈、正确性信号与测试通过率，可获得互补改进。
  • 多数收益集中于早期迭代，可据此设计停止策略，在准确率、token 消耗与 API 成本之间进行权衡。
  • 评测 LLM 时应纳入其从交互经验中持续改善的能力，而不应只考察静态零样本表现。
