SIM：经验记忆驱动持续改进

用可续写的自我改进记忆保存修改依据与结果，帮助智能体跨模型、跨数据集持续优化外部程序。

★ 3 子主题：递归自我改进 机器之心  MemoryEvolve AgentEvolve SystemEvolve

 递归自我改进 智能体记忆 智能体脚手架演化 持续学习 自我改进

论文：https://arxiv.org/abs/2611.18856
原文：https://mp.weixin.qq.com/s/BdT-t4JQivNji9OIax89-A
用途

在需要跨模型或跨任务持续优化智能体 harness 的系统中，可借鉴 SIM 记录修改依据、预测与实测结果，并将其供后续优化器检索和修订。

启示

可迁移的自我改进资产不应只有最终代码，还应包含可审查的修改因果记录，使后续优化能区分应保留的原则与需适配的实现。

📄 详细内容
  • 问题：智能体切换任务模型、数据集或基准后，如何复用此前的优化经验，避免重新搜索外部执行程序。
  • 旧法为何失效：仅迁移优化后的 harness 会丢失修改意图，源环境中的代码还可能不适合新环境；例如 Opus 优化的 harness 交给 Gemini 后仅得 68.41，低于其种子 harness 的 73.89。
  • 方法：提出自我改进记忆 SIM，按问题保存 harness 修改内容、理由、预期与实际结果及评估背景，并让候选生成和筛选组件读取、追加和修订这些记录。
  • 实验：覆盖编码、文本分类、工作空间和工程设计；六个跨数据集设置及四个 Opus 到 Gemini 设置中，完整 SIM 均优于仅迁移 harness 或根因标签。工作空间实验由 68.41 提升至 84.75，而仅迁移 harness 为 73.42；编码领域十组独立运行中九组领先，平均高 2.36 分，95% CI 为[1.05, 3.68]。
  • 局限与后续：方法要求新旧环境接口兼容，收益并非每次迁移都存在；当前未保存所有落选候选，长期记忆的上下文成本、检索机制与可扩展性仍待验证。

Harness Learning：反馈驱动的框架元学习

训练4B提案者从执行反馈中迭代修改框架，让冻结模型跨任务提分，平均表现超过35B教师。

★ 3 子主题：脚手架演化 微信公众平台  HarnessEvolve SystemEvolve

 智能体脚手架演化 强化学习 元学习 执行反馈 跨域泛化

原文：https://mp.weixin.qq.com/s/_HXvEUAzS0JE2vbdyTYL5g?scene=1
用途

在需要适配新任务的智能体系统中，可借鉴提案者与执行反馈闭环，在冻结基础模型时自动迭代运行框架代码。

启示

智能体的适应能力可以外置为针对可执行框架的学习规则，跨任务提升不必依赖模型权重更新。

📄 详细内容
  • 问题：如何让智能体自动学习修改运行框架，并将这种修改能力迁移到训练时未见的任务，而不更新求解模型参数。
  • 旧法为何失效：人工测试时反复修改框架费时费力，针对单一任务搜索出的改法也常难以迁移；独立生成多个候选还依赖高成本的最优选择。
  • 方法：将框架修改视为可执行程序上的元学习；提案者读取任务、当前框架和执行报告后生成代码修改，通过SFT初始化并以可验证奖励和GRPO训练，测试时冻结提案者与求解器，仅串行迭代框架。
  • 实验：在21个未见Reasoning Gym任务家族上，单步修改平均分由0.32升至0.62，超过35B教师的0.56；在MuSiQue上，10轮串行修改将精确匹配率从独立修改平均0.15提升至0.27，并迁移到MuSiQue和2WikiMultihopQA。

AutoRLBench：真实RL故障诊修评测

用真实强化学习事故评测智能体的诊断修复能力，最高整体通过率仅33.3%。

★ 2 子主题：智能体评测 GAIR DAO  EvalEvolve AgentEvolve CodeEvolve HarnessEvolve

 智能体评估 模型评估 强化学习 故障归因 执行验证

代码：https://github.com/Thinking-Space/AutoRLBench
原文：https://mp.weixin.qq.com/s/vLofmaxMiJd77bGxG9ufcA
用途

在强化学习训练智能体或AI辅助研发系统中，可直接部署其代码作为诊断、根因定位和修复能力的评测基线。

启示

发现训练已经失败远比解释失败原因容易，可靠的自动修复必须联合代码、配置、日志与完整训练结果形成可执行证据链。

📄 详细内容
  • 问题：强化学习训练可能在没有显式报错时因数据、奖励、算法、环境或基础设施故障而失效，需要检验智能体能否定位根因并完成可靠修复。
  • 旧法为何失效：以往评测只看智能体能否跑完训练流程或取得最终分数，无法区分异常发现、根因解释与有效修复，也容易忽略静默崩溃和短期假改善。
  • 方法：AutoRLBench 收集38个、现已扩展至50个真实RL事故现场，保留代码、配置、日志、评估记录和运行环境；Diagnosis要求判断健康状态、定位根因并举证，Repair要求修改工作区并在干净环境中重跑验证。
  • 实验：初步评测覆盖10个前沿模型、380条诊断轨迹和180条修复轨迹；82.8%的轨迹能发现训练异常，但仅16.1%定位正确根因，最高整体通过率为33.3%，且观察到奖励作弊行为。
  • 局限与后续：基准仍在持续扩充，团队正征集无显式报错、多组件耦合、需要长链推理或仅在训练后期暴露的可复现故障。

NightWatch：主动流式界面感知

用轻量监视器持续追踪动态界面，解决计算机操作智能体因快照过时而误操作和空等的问题。

★ 2 子主题：状态追踪 Hugging Face Papers  AgentEvolve HarnessEvolve

 智能体 状态追踪 图形用户界面智能体 长程任务 成本优化

论文：https://arxiv.org/abs/2611.28947
用途

在桌面、动态网页或移动端长程操作智能体中，可借鉴NightWatch的轻量流式监视器，在主模型推理期间持续校验界面状态并避免执行过时动作。

启示

动态环境中，决定何时重新感知与感知到什么同等重要，持续的低成本状态同步可比扩大决策模型更有效地缩小感知—动作间隙。

📄 详细内容
  • 问题：桌面、网页和移动端界面会自主变化，而计算机操作智能体只观察离散截图；视觉语言模型的推理延迟会使执行动作时所依据的状态已经过时。
  • 旧法为何失效：逐轮截图无法提供实时态势感知，被动监视方法还会造成无效等待，形成明显的感知—动作间隙。
  • 方法：NightWatch在不修改智能体模型、提示或动作空间的情况下，接入仅0.8B参数的System-1监视器NightWatch-0.8B，以低延迟流式追踪界面并将决策锚定到当前状态。
  • 实验：在OSWorld-Verified上保持任务成功率相当，同时将非推理耗时降低33%、浪费时间降低53%；在DynaCU-Bench上将大型VLM智能体成功率从39.5%提升至44.2%，效率优于AOI、PUSV及规模大30倍以上的System-1决策模型。

ACAP：异步多智能体机器人控制

用异步常驻编码智能体并行控制机器人部件，以动态协调处理物理依赖，任务耗时降低28.2%。

★ 2 子主题：多智能体系统 Hugging Face Papers  RobotEvolve NewApply

 具身智能 多智能体系统 任务规划 系统优化 人工智能辅助编程

论文：https://arxiv.org/abs/2611.31205
用途

在多臂或移动操作机器人系统中借鉴ACAP的异步控制组与动态协调机制，并将其作为单智能体控制和固定分工策略的对比基线。

启示

机器人控制的主要延迟并非必须通过更快的单体推理解决，而可通过部件级异步自治、仅在物理依赖出现时集中协调来消除。

📄 详细内容
  • 问题：单个编码智能体控制整台机器人时，彼此独立的部件也必须等待串行推理与执行，拖慢复杂机器人任务。
  • 旧法为何失效：单智能体直接策略无法并行处理独立动作；固定分工又难以协调存在物理依赖、需要紧密配合的机器人部件。
  • 方法：ACAP将一台机器人组织为多个常驻智能体，每个成员负责可配置的控制组并异步推理执行；超智能体负责分配任务、协调依赖，并在主智能体与成员间动态配置控制权。
  • 实验：在覆盖25种任务与平台设置的72次真实机器人运行中，相比单智能体Direct Policy，任务平衡耗时降低28.2%；在全部8个协作设置中优于Fixed Delegation，另有90次运行显示其在6项任务上的30分钟封顶平均耗时均低于Direct。
  • 局限与后续：工作发布包含观测、生成程序、动作和反馈的真实运行数据，供后续研究编码智能体在物理世界中的推理与行动。
