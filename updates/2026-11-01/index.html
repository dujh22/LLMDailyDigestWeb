ActionOPD：面向智能体决策的动作级在策略蒸馏

清华大学提出 ActionOPD，在学生实际访问的状态上通过语义动作奖励蒸馏教师决策，无需教师 Token 概率或同源 Tokenizer，并支持跨模型家族及同模型自蒸馏。

★ 2 子主题：在策略蒸馏 机器之心  AgentTrainEvolve

 在策略蒸馏 智能体 模型蒸馏 强化学习 工具调用

论文：https://arxiv.org/abs/2610.19820
代码：https://github.com/thu-nics/ActionOPD
原文：https://mp.weixin.qq.com/s/IX2R7pRSkuOAEvb6dB9DBw

ActionOPD 不再逐 Token 模仿教师，而是在学生实际访问的状态上，对工具调用或用户回复的高层语义动作进行对齐，从而缓解多轮交互中的状态分布偏移。该方法将期望教师动作似然转化为 REINFORCE 策略梯度，以师生动作的语义一致性作为奖励，无需访问教师 log-prob，也不要求师生采用相同 Tokenizer。其 State-Group Rollout 并行采样师生动作，以最高分候选推进环境，并复用全部学生候选通过 PPO 风格目标更新策略。实验显示，该方法可实现跨模型家族蒸馏并提升多个未见基准上的零样本泛化；Self-ActionOPD 还利用特权上下文让同一模型完成动作级自蒸馏。

用途与启示
  • 为黑盒教师与异构模型之间的智能体能力迁移提供可行方案，教师选择可侧重决策质量而非架构和词表兼容性。
  • 将蒸馏监督从表面 Token 模仿提升到语义动作对齐，使学生能够保留自主推理路径和表达方式。
  • 通过学生在策略状态采样减少训练与部署时的状态分布偏移，适合多轮工具调用和复杂环境交互。
  • 特权上下文驱动的 Self-ActionOPD 为智能体自蒸馏和自我进化提供了新路径。

  • CLASHarness覆盖20个真实领域、600个多轮冲突任务、7,970张4K视觉证据图片和3,284项检查点，并通过“三层八阶段”管线保障任务可执行与可验证。
  • 对15个主流模型的9,000余条沙盒轨迹评测显示，模型单项检查平均得分可达55%–67%，但端到端通过率均未超过30%，主要失败于修复、交接和释放共享资源等完整执行链条。
  • 强模型更能主动查看图片核验环境真值，而关闭视觉输入会使通过率下降87%–90%；弱模型则更容易盲信存在错误的队友文字汇报。
  • 增加思考Token可能导致重复调用工具和步数耗尽，适度放宽交互步数反而能提升长线探索效果；框架还可合成带可验证奖励的多模态冲突训练轨迹。
用途与启示
  • 用于审计智能体在队友信息与环境证据冲突时的核验、纠错和可信执行能力。
  • 为多智能体系统补充共享锁释放、工单关闭、下游通知等容易被传统基准忽略的收尾评测。
  • 可利用模块化冲突插件生成可验证训练数据，训练不盲从队友且能主动取证的智能体。
  • 提示系统设计者应联合优化推理预算、交互步数和工具调用策略，避免过度思考造成执行死循环。
