Karpo Decision：单次前向并行决策

用单次前向并行打分取代逐词生成，解决智能体高频决策慢且贵的问题，31B版中位延迟94毫秒。

★ 3 子主题：推理效率 新智元  JevEvolve

 推理加速 智能体 成本优化 不确定性估计 模型训练

原文：https://mp.weixin.qq.com/s/FR8k0oNTcKvlPMJDeor9qw
用途

在浏览器智能体、本地生活助手和大规模候选筛选系统中部署其开源模型，用一次前向并行完成动作选择、分类与置信度判断。

启示

智能体的高频动作选择无需依赖文本生成，把决策建模为校准的并行候选打分，可同时改善延迟、成本与可控性。

📄 详细内容
  • 问题：通用生成模型执行浏览器操作等高频决策时，需要逐词输出推理过程，带来高延迟、高Token成本和置信度失准。
  • 旧法为何失效：全参数微调虽能提高公开榜成绩，却使陌生领域准确率下降2.3个百分点；正反读取选项等技巧还会让延迟翻倍，难以反映真实泛化能力。
  • 方法：Karpo Decision移除逐词解码，以线性Readout head在一次前向中并行评估最多255个选项；Branch Attention共享长上下文的KV缓存，并结合RSI筛选闭环、五检查点Model Fusion及校准决策强化学习RLCD。
  • 实验：31B版在Decision Index的300个模型中以73.9分居首，中位延迟94毫秒；When2Call与Mind2Web分别达到90.4%和90.0%，JevBench校准误差ECE为0.023，每千次决策成本0.025美元。

自我改进分支混合：动态目标与路由组合

用动态分支目标、经验化提案策略和路由器，避免智能体脚手架搜索陷入单一路径与局部最优。

★ 3 子主题：脚手架优化 未知  HarnessEvolve SystemEvolve

 智能体脚手架演化 递归自我改进 模型路由 进化搜索 执行反馈

原文：https://mp.weixin.qq.com/s/VRcBgDS5gA6MiI3MoTOqTw?scene=1
用途

在智能体工作流或代码脚手架自动优化系统中，借鉴动态开发集分流、分支局部提案更新和任务级路由机制，以保留并组合互补能力。

启示

脚手架自我改进的关键不只是并行增加候选，而是让不同搜索分支持续形成差异化目标与经验，从而产生可路由组合的能力互补。

📄 详细内容
  • 问题：现有智能体 Harness 自我改进沿单一搜索轨迹演化，容易忽略整体排名不高但具有独特解题能力的候选，并收敛到局部最优。
  • 旧法为何失效：Meta-Harness 等方法始终使用固定开发集和固定提案策略，无法随搜索历史调整目标，也难以保留不同候选的互补能力。
  • 方法：建立多个并行分支，依据各分支领先 Harness 的独占解题覆盖动态划分开发子集，并定期从分支历史中更新局部 proposal guidance；搜索结束后用仅基于开发数据配置的 router 为每个新任务选择分支 head。
  • 实验：在奥林匹克级数学推理、Terminal-Bench 2.0 和 SWE-bench Lite 上，相对 Meta-Harness 分别最高提升 34.8%、11.6% 和 3.8%；Math–Gemini 中准确率由 46.0% 提升至 62.0%。
  • 局限与后续：router 在四个设置中仅两项超过最佳单分支 head，且搜索 token 成本约为 Meta-Harness 的 1.55至2.16 倍；效果与路由上下文、任务及更新频率相关。

SWE-CoWork：数字员工式编程评测

★ 2 子主题：智能体评测 Hugging Face Papers  EvalEvolve CodeEvolve HarnessEvolve

 智能体评估 人工智能辅助编程 长程任务 多智能体协作 执行验证

论文：https://arxiv.org/abs/2611.20218
用途

在仓库级编程智能体研发中，将其作为组织协作与完整交付基准，评测需求获取、实现、验证和交接的端到端可靠性。

启示

编程智能体的核心瓶颈并非单次获取需求，而是把需求持续绑定到实现、验证与交接全过程，完整信息本身不足以保证完整交付。

📄 详细内容
  • 问题：组织中的编程智能体不仅要写代码，还需从同事和工作记录中恢复分散需求、化解冲突，并验证和交付完整功能。
  • 旧法为何失效：既有编程评测通常直接提供明确需求，难以衡量智能体在真实组织协作中的需求澄清、持续跟踪与交付能力。

  • 实验：评测11个模型后，领先模型通过约63%的失败转通过测试，但完整任务成功率不足8%；预先提供完整需求可使Seed Evolving和GPT-6 Astra的测试通过率提升约16个百分点，却未提高完整任务成功率。Claude-Opus-5.5有93%的首次提问指向责任人，但仅获得64%的同事持有需求，且31%自报完成的需求未通过测试。

Accelerate Bench：应用级程序优化评测

用完整应用与独立验证器评估编程智能体能否在保持正确性的同时实现端到端加速。

 人工智能辅助编程 模型评估 智能体评估 系统优化 执行轨迹

论文：https://arxiv.org/abs/2611.20882
用途

在编程智能体或优化脚手架开发中，可将其32项可执行任务、独立验证器和轨迹作为应用级性能优化基准。

启示

应用优化收益并非局部改动的简单叠加，构建配置、运行环境及改动间相互作用是决定最终加速幅度的核心因素。

📄 详细内容
  • 问题：应用级优化要求编程智能体在完整程序中发现并协调多处改动，同时保持计算正确性，局部代码优化能力不足以反映实际效果。
  • 方法：Accelerate Bench 收录32个源自科学应用和超算竞赛的CPU优化任务，明确工作负载、正确性要求、计时边界与允许修改范围，并以公开测试支持迭代、独立验证器评判最终提交。
  • 实验：在1.1版上评测16个“模型+脚手架”组合，Score@1为25.5%至67.4%；前两名在至少22个任务上达到2倍加速，其余14个仅在8至17个任务上达到该水平。
  • 实验：受控回放显示，相同源码仅因构建与运行配置不同即可产生0.29倍至2.12倍性能差异；同一代码改动因与其他改动组合不同，收益可从1.01倍变为6.4倍。
