Manager Loop：GPT-6 多智能体一周搭建虚拟曼哈顿

TGOPD：蒸馏前验证的提示级教师门控

TGOPD 在提示级验证教师可靠性，并在稠密在策略蒸馏与基于验证器的 GRPO 之间动态路由，从而提升训练效果和教师算力利用率。

子主题：在策略蒸馏 Hugging Face Papers 

 在策略蒸馏 模型蒸馏 模型训练 验证器 强化学习

论文：https://arxiv.org/abs/2609.02998

传统在策略蒸馏对所有提示统一采用冻结教师的词元级监督，但反向 KL 的模式寻求特性会放大教师自信却错误的指导。TGOPD 使用少量经验证器评分的教师探测结果，在提示级估计教师可靠性：验证通过时执行稠密 OPD，否则切换至基于验证器反馈的 GRPO。该方法在数学、代码和指令遵循任务的 4B、35B 学生模型上均优于 Vanilla OPD，并提高多领域训练下的七项基准平均成绩。通过利用原本闲置的教师容量进行可靠性估计，TGOPD 在实测 4B 单领域异步训练中将教师节点 GPU 利用率从 9.8% 提升至 78.9%。

用途与启示
  • 为在策略蒸馏引入结果正确性验证，避免不可靠教师产生强烈但误导性的梯度更新。
  • 将教师可靠性作为提示级路由信号，在蒸馏监督与强化学习之间自适应选择训练策略。
  • 说明验证器不仅可用于奖励建模，也可作为控制知识蒸馏监督准入的门控机制。
  • 为异步蒸馏系统提供提升教师节点 GPU 利用率、减少闲置算力浪费的工程方案。

对话生成工件的修订传播与经济型测试时计算

论文提出对话生成工件的修订传播基准，并发现从三个并行样本中进行模型或中心样本选择，能以较低成本将准确率提升2.2至9.7个百分点。

Split-LLM 训练隐私失效：返回梯度暴露真实数据行

研究发现 Split-LLM 训练中返回云端的输出梯度会以零梯度模式区分诱饵与真实数据行，使仅检查前向通道的隐私评估产生虚假安全结论。

子主题：安全评测 Hugging Face Papers 

 隐私泄露 数据安全 模型训练 人工智能可靠性 安全审计

论文：https://arxiv.org/abs/2609.04382

研究考察了由可信本地节点与不可信云节点组成的双节点 Split-LLM 训练系统：本地端发送混有诱饵行的受保护激活，并在计算私有损失后向云端返回输出梯度。由于损失函数忽略诱饵，其梯度严格为零，云端可据此准确识别真实行；在九个随机种子下，每次实验均识别出全部 4,096 个真实行。基于帧内容的攻击相较恒定猜测基线，每百个词元可额外恢复约一个词元，而打乱标签的对照实验未检测到泄漏。逐行裁剪并加噪可在约 0.01 nats 留出集交叉熵代价下关闭该通道，但跨训练步骤累积观测等五类攻击仍未得到评估。

用途与启示
  • 提醒 Split Learning 与隐私训练系统必须审计完整的双向协议，不能只验证前向激活通道。
  • 可将零梯度模式、梯度稀疏性及跨步骤累积泄漏纳入隐私威胁模型和安全评测基准。
  • 表明诱饵机制需要同时覆盖损失与反向传播路径，否则诱饵身份可能被梯度直接揭示。
  • 为梯度逐行裁剪、加噪等防护措施提供了效果与模型质量成本的定量参考。

FlowBalance面向推理模型从自身同策略经验中学习时监督稀疏、自信错误被强化以及解法模式过度集中的问题。方法由冻结的同一策略借助特权上下文计算词元级对数概率增益，并聚合为轨迹级自引导分数，再依据验证器给出的组优势保留、反转或禁用该信号。它通过轨迹平衡拟合指数重加权后的归一化目标分布，无需额外的词元级模仿损失，并具备组内对比保持、最小变化反向 KL 和纠正假阳性引导等理论性质。在 Qwen3-4B 与 Qwen3-8B 的数学推理实验中，该方法优于 FlowRL，同时提升训练速度、稳定性和正确策略多样性，并避免直接 OPSD 导致的回答长度坍缩。
