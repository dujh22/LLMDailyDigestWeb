持续在线个人智能：三模块持续闭环

用感知、记忆、行动持续协同的闭环，定义无需用户反复唤醒且能安全自我改进的个人助手。

★ 3 子主题：智能体框架 新智元  PersonalEvolve AutonomousAgentEvolve MemoryEvolve

 智能体 常驻智能体 状态持久化 自演化 智能体记忆

原文：https://mp.weixin.qq.com/s/YHbLlX368ac6qccGvIJNxw
用途

在个人助理、可穿戴设备或具身智能系统设计中，借鉴三模块六通道框架与L0-L5分级审查持续运行、状态保留和安全自演化能力。

启示

持续在线不是后台驻留或单项记忆能力，而是跨请求维持感知、记忆与行动协同，并由用户边界约束机制演化的系统属性。

📄 详细内容
  • 问题：个人助手即使能后台运行，也常在对话结束后丢失承诺、错过变化或停止自主决策，尚缺乏对“持续在线”的统一定义与发展路线。
  • 旧法为何失效：单独增加长期记忆、主动搭话或定时任务，只能实现状态保留或机械触发；感知遗漏、错误记忆反复调用和行动结果延迟，还会造成“记忆陷阱”与重复执行。
  • 方法：综述632篇文献及119个系统和产品，将持续在线定义为“运行连续性+状态持久性”组成的持续闭环，并以感知、记忆、行动三个模块及六条有向通道刻画系统；进一步提出L0至L5分级、受用户边界约束的自演化证据链，以及诊断工具HALO。
  • 实验：对119个系统定级后，52个尚未达到持续在线，67个达到可自主决定行动或等待的L3及以上；仅5项研究达到受用户边界约束的L5，尚无公开产品达到该级别。
  • 局限与后续：产品等级仅依据公开资料，代表可验证能力的下限；未来需补足感知遗漏、长期记忆正确性、延迟结果评估及自我修改可追溯、可检查、可撤回等能力。

用途

  • 问题：现有智能体通常只会调用技能，技能的创建和更新仍依赖教师模型、规则或外部模块，难以形成自主的长期能力演进。

DeLoop：重复动作自监督脱环

用同一轨迹中的重复调用与恢复动作自动构造偏好数据，减少长程智能体空转并降低交互成本。

★ 2 子主题：经验学习 Tau Lab  AgentTrainEvolve DataEvolve

 智能体 长程任务 模型训练 偏好优化 成本优化

论文：https://arxiv.org/abs/2610.19376
原文：https://mp.weixin.qq.com/s/h3aLY1sNkEFrr9OjLLvJYw?scene=1
用途

在长程工具调用智能体的后训练中，从执行日志自动挖掘“重复动作—恢复动作”偏好对，并用DPO降低循环调用和运行成本。

启示

智能体的无效循环并非只有负面价值，其后续自发恢复行为能把失败轨迹转化为无需外部标注的纠错监督信号。

📄 详细内容
  • 问题：长程智能体会反复执行参数及观察结果均相同的工具调用，消耗生成与执行预算；历史压缩还会使其更容易忘记已经尝试过的动作。
  • 旧法为何失效：传统纠错训练依赖任务奖励、标准答案或大模型裁判，标注成本较高；摘要或截断历史又会丢失已执行动作，使循环率最高升至约65%。
  • 方法：DeLoop从轨迹中检测完全重复的调用与观察，将循环动作作为负例、后续首个脱离循环的恢复动作作为正例，并通过DPO训练策略，无需外部奖励或裁判。Qwen3-8B使用自身CodeGym轨迹挖出的8,000对样本训练一个epoch。
  • 实验：在300个CodeGym留出任务上，DeLoop将循环任务比例从57.3%降至6.1%，平均步数从15.00降至4.67，token消耗从约23.9k降至12.7k，成功率由25.1%微升至25.9%；14B和32B成功率分别提升7.2和7.1个百分点。混合4,635对跨环境数据后，成功率达到30.3%，并在BrowseComp-Plus上将循环率从22.4%降至1.2%。
  • 局限与后续：当前仅能检测调用、参数和观察完全相同的结构性循环，无法覆盖形式变化的语义循环；持续未脱环的轨迹也不能产生偏好对。核心训练证据集中于Qwen3，部分跨环境实验仅运行一次，且减少循环不保证成功率提升。

RiseHarness：双轨迹驱动脚手架进化

用成功与失败运行的双轨迹对照迭代改进执行脚手架，提升长程终端智能体重复完成任务的稳定性。

★ 3 子主题：脚手架演化 未知  HarnessEvolve SystemEvolve

 智能体脚手架演化 长程任务 人工智能可靠性 执行轨迹 终端任务

原文：https://mp.weixin.qq.com/s/VIRKJrfm2J9LqkQw_1eQoQ?scene=1
用途

在长程终端智能体系统中借鉴其双轨迹诊断与版本采纳机制，在不更新模型权重的情况下持续优化命令执行、反馈和完成确认流程。

启示

智能体“有能力但不稳定”的根因常在模型特定的交互脚手架中，因此运行时机制应按模型行为适配，而不能假设整套配置可跨模型通用。

📄 详细内容
  • 问题：长程终端智能体可能偶尔完成任务，却因局部错误沿操作和上下文传播，难以在重复运行中保持稳定成功。
  • 旧法为何失效：只观察模型操作会忽略命令执行、反馈组织、上下文管理和完成判定中的脚手架问题；统一脚手架配置也无法适配不同模型的行为模式。
  • 方法：RiseHarness 对照结果翻转任务的成功与失败运行，联合分析智能体轨迹和脚手架内部轨迹，并借助脚手架手册定位共享机制；候选改动参考其他框架，经行为检查和重复评测后，仅保留实测提升的版本，全程固定模型权重。
  • 实验：在 Terminal-Bench Hard 的100项任务上进化，并在 Terminal-Bench 2.1的89项任务上测试，每项重复4次。DeepSeek-V4-Flash在TBH上的Pass@1由56.75%升至64%，四次全过比例由37%升至51%；GPT-6-sol的对应指标由50.25%升至55.50%、39%升至46%。
  • 局限与后续：方法无法自然覆盖始终失败或监控前已失败的运行；改进具有模型和基准依赖性，四次重复也不足以代表更多运行环境下的可靠性。

用审核智能体把专用脚手架的纠正转成可执行轨迹，移除脚手架后成功率仍由23.3%升至44.3%。

原文：https://mp.weixin.qq.com/s/37PsXqObNN0ZAzLCrwxK7Q?scene=1
用途

在需要统一部署脚手架的工具型智能体中，可借鉴执行前审核与轨迹微调机制，把专用流程能力压入模型权重后仅保留简化运行环境。

启示

监督轨迹与学生当前状态及目标动作空间的匹配度，比教师轨迹本身的成功率或教师能力更能决定行为能否被内化。

📄 详细内容
  • 问题：专用 agent harness 能增强工具调用、上下文管理和状态控制，但部署时必须持续挂载并路由不同脚手架，难以构建统一智能体。
  • 旧法为何失效：优化脚手架与目标脚手架拥有不同的动作空间和可见信息，无法直接把前者的轨迹用作监督；更强教师生成的高成功率轨迹也未必适合学生学习。
  • 方法：HARNESS-ZERO 让学生始终在固定 target harness 下响应，再由掌握私有参考信息的 Agent-as-Harness 在执行前放行或纠正；审核后的学生可执行轨迹用于监督微调，部署时移除专用脚手架和审核智能体。
  • 实验：在 SpreadsheetBench、AppWorld 和 USPTO 上，Qwen3.5-9B 的宏平均成功率由23.3%升至44.3%，超过保留专用 meta-harness 的41.7%；28种脚手架专属行为平均恢复率为82.3%。前沿模型实验中，Agent-as-Harness 平均得分81.1%，高于 code-as-harness 的78.1%。
  • 局限与后续：方法依赖强审核模型，逐轮审核使 USPTO 数据收集延迟增至2.4倍；监督微调对深层领域知识及难以写入响应的上下文管理机制内化有限。

  • 方法：MEM-SQL 分层存储完整查询模板、可复用 SQL 块及领域概念到模式元素的映射，仅在该层所有需求都达到匹配阈值时启用；按需模式链接 OSL 只在无记忆层合格或生成器认为证据不足时查询数据库模式。
  • 实验：HARE 基准包含来自4个数据集的1,600个请求和823条已验证查询；在6个语言模型上，MEM-SQL 将平均执行准确率由37.1%提升至50.0%，输入词元减少76.6%，延迟降低68.8%。
  • 局限与后续：组合复用多条历史查询仍是瓶颈，准确率由56.7%降至29.7%；当复用组件需嵌入新结构或与共享连接组合时下降最明显。
