Terminal-RSI：递归改写与策略精炼

交替保留已验证行为并精炼策略，解决终端智能体局部修复难以汇聚为完整成功的问题，宏平均成功率提升29.90个百分点。

 递归自我改进 智能体 模型训练 强化学习 长程任务

论文：https://arxiv.org/abs/2610.22192
原文：https://mp.weixin.qq.com/s/LI2edgZxywDY3qA8yGbYvw?scene=1
用途

在终端操作或仓库修复智能体训练中，借鉴RSR-RPR交替循环、critic继承校准和TB-GAE，将已验证的局部修复逐轮转化为完整任务成功。

启示

递归改进能否持续，关键不在重复训练次数，而在于只跨阶段传递经验证的行为与已校准的价值判断，使局部进展始终受最终成功约束。

📄 详细内容
  • 问题：终端智能体常能修复依赖或通过局部检查，却无法达到受保护验证器要求的完整终态；长日志还会干扰跨交互回合的信用分配。
  • 旧法为何失效：标准GAE会让观察文本长度影响优势衰减，统一的局部奖励又可能使失败轨迹获得过高回报；策略反复改写后，旧critic也难以适应新策略与奖励分布。
  • 方法：Terminal-RSI交替执行递归自我改写RSR与递归策略精炼RPR，只保留通过验证和泄漏检查的轨迹，并继承critic，经预热校准后联合优化。TB-GAE按交互回合而非日志token分配信用，FDR与SPR则按任务家族校准局部进度并优先奖励严格成功。
  • 实验：在Terminal-Bench 2.1、3.0、4.0、Hard、LHTB和SWR100上评测，27B模型的四套Terminal-Bench宏平均成功率达到50.58%，较Base提升29.90个百分点；LHTB严格完成数由0/46升至5/46。对4,352条轨迹重评分后，失败轨迹的奖励占比由50.09%降至28.72%。
  • 局限与后续：五阶段同时改变数据、奖励、学习率和初始化，缺少计算量匹配的组件消融；目前主要验证单一27B基座，评测重复次数有限，验证器也无法保证未编码的架构要求得到满足。

用从种子框架自主创建并迭代的基准，解决执行框架长期被固定评测的问题，并揭示反馈优化易过拟合。

 智能体脚手架演化 智能体执行框架 智能体评估 自演化 跨域泛化

论文：https://arxiv.org/abs/2609.01437
原文：https://mp.weixin.qq.com/s/whH7PVjIxsRateDXjCamnA?scene=1
用途

在智能体执行框架研发中，可借鉴其Creation/Evolution协议，将框架创建、反馈迭代、跨模型迁移和未见任务测试纳入验收流程。

启示

执行框架本身是智能体能力的一部分，而只针对当前模型和反馈集优化会形成脆弱的模型—框架耦合，无法等同于可泛化的自我进化。

📄 详细内容
  • 问题：智能体能力不仅取决于模型，也取决于负责工具调用、上下文管理、错误恢复和验证的执行框架，但现有评测很少衡量模型能否自行开发并改进该框架。
  • 旧法为何失效：传统评测固定 LangChain、AutoGPT 等框架后只比较模型，无法区分模型与框架贡献，也无法检验框架的跨模型迁移和持续改进能力。
  • 方法：HarnessDev 分为 Creation 与 Evolution 两阶段；6 个模型先把得分为零的极简种子扩展为完整框架，再依据独立反馈任务迭代10轮，并在未见测试集及固定执行模型上检查泛化。
  • 实验：基准覆盖代码、数据分析、写作和网页研究共5项测试；生成框架在写作和数据分析上可超过人类基准，但研究任务最佳成绩52.6，较人类92.2仍低39.6分。Qwen反馈集提升13.9%而测试集仅提升1.43%，Opus框架换用Gemini执行后在SWE-Pro上从69.3降至33.0。
  • 局限与后续：目前仅覆盖4个领域，每个模型只有1条进化轨迹，且开发环境保持固定；后续需增强跨模型泛化、安全改造能力，并研究用进化后框架继续开发下一代框架。

SkillMaster：策略内生技能进化

把技能编辑纳入智能体策略，并用下游任务效用训练其自主创建、修订和保留可复用技能。

★ 3 子主题：技能演化 机器之心  HarnessEvolve AgentEvolve

 智能体 技能演化 强化学习 经验学习 递归自我改进

论文：https://arxiv.org/abs/2605.08693
代码：https://github.com/sduyangmin/Skill-Master
原文：https://mp.weixin.qq.com/s/l7MxH1DPsVtqz4OZSF8lxg
用途

在长期运行的任务智能体中借鉴反事实技能效用奖励和 DualAdv-GRPO，使智能体能从执行轨迹中自主维护并复用技能库。

启示

技能编辑的价值应由其对后续相似任务的因果效用衡量，而非由当前任务成败或外部教师的判断替代。

📄 详细内容
  • 问题：现有智能体通常只会调用技能，技能的创建和更新仍依赖教师模型、规则或外部模块，难以形成自主的长期能力演进。
  • 旧法为何失效：任务最终成败无法区分执行能力与技能质量，也难以判断某次技能编辑是否真正改善了后续任务。
  • 方法：SkillMaster让同一策略通过 propose_skill、update_skill 和 keep_skill 管理技能；以原技能库和修改后技能库在相关探测任务上的反事实差异计算效用奖励，再用 DualAdv-GRPO 分别估计任务执行与技能管理优势并联合训练。
  • 实验：基于 Qwen2.5-7B-Instruct，在 ALFWorld、WebShop 和 SearchQA 上分别取得 98.7%、82.0% 和 48.0%，前两项较 SkillRL 提高 8.8 和 9.3 个百分点；WebShop 测试时从空技能库自主构建技能，使成功率由 65.63% 升至 71.88%。
  • 局限与后续：目前主要验证于结构化交互和搜索问答环境；开放环境仍需降低效用评估成本，并支持技能删除、跨智能体共享及分布变化下的持续学习。

HARNESS-ZERO：智能体驱动的脚手架蒸馏

用审核智能体把专用脚手架的纠正转成可执行轨迹，移除脚手架后成功率仍由23.3%升至44.3%。

★ 3 子主题：脚手架优化 Tau Lab  HarnessEvolve AgentTrainEvolve

 模型蒸馏 智能体脚手架 智能体 执行轨迹 工具调用

原文：https://mp.weixin.qq.com/s/37PsXqObNN0ZAzLCrwxK7Q?scene=1
用途

在需要统一部署脚手架的工具型智能体中，可借鉴执行前审核与轨迹微调机制，把专用流程能力压入模型权重后仅保留简化运行环境。

启示

监督轨迹与学生当前状态及目标动作空间的匹配度，比教师轨迹本身的成功率或教师能力更能决定行为能否被内化。

📄 详细内容
  • 问题：专用 agent harness 能增强工具调用、上下文管理和状态控制，但部署时必须持续挂载并路由不同脚手架，难以构建统一智能体。
  • 旧法为何失效：优化脚手架与目标脚手架拥有不同的动作空间和可见信息，无法直接把前者的轨迹用作监督；更强教师生成的高成功率轨迹也未必适合学生学习。
  • 方法：HARNESS-ZERO 让学生始终在固定 target harness 下响应，再由掌握私有参考信息的 Agent-as-Harness 在执行前放行或纠正；审核后的学生可执行轨迹用于监督微调，部署时移除专用脚手架和审核智能体。
  • 实验：在 SpreadsheetBench、AppWorld 和 USPTO 上，Qwen3.5-9B 的宏平均成功率由23.3%升至44.3%，超过保留专用 meta-harness 的41.7%；28种脚手架专属行为平均恢复率为82.3%。前沿模型实验中，Agent-as-Harness 平均得分81.1%，高于 code-as-harness 的78.1%。
  • 局限与后续：方法依赖强审核模型，逐轮审核使 USPTO 数据收集延迟增至2.4倍；监督微调对深层领域知识及难以写入响应的上下文管理机制内化有限。

Harness-of-Harness：证据驱动持续开发

用规划、开发与独立测试组成证据闭环，让编码智能体持续交付完整软件，三轮平均相对提升52.25%。

 人工智能辅助编程 长程任务 智能体执行框架 SWE 软件工程 执行验证

原文：https://mp.weixin.qq.com/s/RkldRsJGOs0tZc40gv0hVA?scene=1
用途

在长周期自主软件开发系统中，可借鉴HoH的角色分工、独立验收和版本化证据机制，为现有编码智能体增加持续迭代与回归控制能力。

启示

长程编码的主要瓶颈不只是单次生成能力，而是能否让版本状态与可验证证据跨轮积累，并持续约束后续决策。

📄 详细内容
  • 问题：编码智能体难以在无人持续监督下完成多日软件开发；新增功能容易破坏旧行为，测试也可能退化为重复检查或过早宣告完成。
  • 旧法为何失效：单次 coding-agent harness 缺少跨轮规划、独立验收和版本状态积累；简单增加运行轮数或 token，不能稳定带来持续改进。
  • 方法：HoH 运行于现有 harness 之上，以规划者、开发者和 QA 测试者组织小步可验证的规划—编码—测试循环，并将版本化软件状态、计划和测试证据传入下一轮。
  • 实验：在 GameCraft-Bench、FrontierSWE 和 ProgramBench 的三组 harness–model 配置上，HoH 三轮平均相对增益52.25%，最高82.86%；超过70轮的多日实验自主开发出可玩的第一人称射击游戏。
  • 局限与后续：受控实验仅覆盖三组配置和有限任务，多日证据来自单一游戏项目；网络或 API 故障仍需人工恢复，尚待更多真实软件项目验证。
