Noam Brown谈多智能体扩展与递归自我改进

OpenAI研究员Noam Brown讨论以大规模并行Agent扩展推理时计算、弱脚手架下的协作涌现，以及多智能体系统推动递归自我改进的潜力与局限。

子主题：多智能体系统 量子位  SwarmEvolve Awesome-RSI

 多智能体系统 多智能体协作 测试时计算 推理 递归自我改进

原文：https://mp.weixin.qq.com/s/6-FqoV2H1ZShD9I-KAQAKg

Noam Brown认为，多智能体系统可将推理时计算从串行思考扩展为并行探索，数学、网页搜索和Deep Research等任务尤其适合这种方式，但扩展效率通常略呈亚线性。OpenAI曾让约1万个Agent运行88小时、生成1300亿token以攻克Navier–Stokes相关难题，不过Brown强调主要贡献仍来自基础模型能力，多智能体的增益尚缺乏充分消融与定量测量。系统尽量减少人工设计的层级脚手架，仅提供Agent间消息传递、上下文分叉等基础工具，使任务分工、争论纠错和共识形成等协作结构自行涌现。访谈还指出，难题耗尽可能限制当前可验证强化学习路线，而具备复制、共享上下文和目标一致性的Agent群体，未来可能被用于自动化研发与递归自我改进。

用途与启示
  • 为多智能体推理系统设计提供思路：优先研究低结构通信、上下文分叉和自组织协作，而非完全依赖固定协调器。
  • 提醒评估大规模Agent系统时区分基础模型能力与并行协作增益，并通过不同Agent规模、成本和延迟的消融实验估计扩展规律。
  • 可将多智能体并行搜索用于数学证明、深度研究及自动化科研等易拆分、可交叉验证的任务。
  • 递归自我改进研究应同时关注高难度训练任务供给、协作冷启动、目标对齐与长程研发任务的监督问题。

阿里云 Agent Sandbox：面向智能体的云上安全执行底座

阿里云 Agent Sandbox 通过 MicroVM 隔离、弹性供给、状态恢复和大规模并发，为智能体训练评测与在线服务提供生产级云上执行环境。

子主题：可信执行 机器之心  EnvironmentEvolve

 智能体 可信执行 安全沙箱 状态持久化 系统优化

原文：https://mp.weixin.qq.com/s/8F2Hu-Xixjnuq3mN1oNolg

阿里云 Agent Sandbox 位于 Agent Infra 执行层，将模型与编排系统生成的行动转化为受控的代码、进程、文件和网络操作，并兼容 E2B Developer API 与 Kubernetes API。其面向 Agentic RL、评测和 RSI 自我进化提供大规模并行环境，支持每分钟创建 10 万个沙箱、单 Region 百万级实例，以及 Checkpoint、Reset、Fork 和 Replay 等状态复用操作。在线服务侧采用 MicroVM、独立身份、Non-root、只读根文件系统、网络策略和日志审计建立安全边界，并通过休眠唤醒保存内存、文件与进程状态。官方称预热后热启动 P99 小于 20 毫秒、深度休眠唤醒 P99 小于 600 毫秒，典型场景整体 TCO 最高可降低 70%。

用途与启示
  • 为智能体运行动态代码、访问文件和调用外部系统提供隔离且可审计的执行环境。
  • 支撑强化学习 Rollout、独立评测和递归自我改进中的大规模并行探索与环境复用。
  • 利用休眠、恢复和按秒计费降低长程任务等待期间的资源占用成本。
  • 提示系统设计者区分沙箱内运行状态与上层业务状态，分别建立持久化和恢复机制。
  • 可作为企业构建生产级 Agent Serving、代码执行及浏览器操作基础设施的架构参考。

Anthropic 发布 Claude Sonnet 5.5，以 Opus 5.5 一半的主要调用价格提供接近其水平的性能，并重点提升编程、长程任务、运行速度与安全防护能力。

Claude Sonnet 5.5 已在 Claude Platform、AWS、Google Cloud 和 Microsoft Azure 上线，模型标识符为 claude-sonnet-5-5。相较 Sonnet 5，新模型输出速度提升超过 30%，完成任务所需 Token 更少，输入、输出及缓存写入价格约为 Opus 5.5 的一半。在 Terminal-Bench 4.0、FrontierCode、CursorBench 和 GDPval-AA 等评测中，其编程与真实工作任务能力显著提升，高 effort 设置下部分成绩接近 Opus 5.5。Anthropic 还针对行为对齐、沙箱逃逸、网络与生物安全以及模型蒸馏攻击部署了审计、任务回退、安全分类器和思考保留等防护措施。

用途与启示

Naive AI 开源 AI 研发模型 Naive-N0.5-Flash

Naive AI 开源由 AI 深度参与架构探索、训练系统、实验迭代与推理优化的 Naive-N0.5-Flash，展示人类负责目标与治理、AI 执行大部分研发闭环的递归自我改进实践。

子主题：递归自我改进 机器之心  EvolveLRM Awesome-RSI EvolveLLM ResearchEvolve

 递归自我改进 模型开发 智能体 模型训练 长上下文 人工智能辅助编程 系统优化 世界模型

原文：https://mp.weixin.qq.com/s/yaoSou6iHhA9eM9uQyBmkw

Naive-N0.5-Flash 是一款面向编程与 AI 研发的 309B 参数混合专家模型，激活参数为 15.5B，原生支持 100 万 token 上下文。模型以 MiMo-V2.5 base 为起点，引入 SWA–DSA 混合稀疏注意力，并经过索引器预热、3T token 继续预训练和 200B token 监督微调。AI 参与候选架构实现、消融实验、数值问题修复、混合序列并行设计及推理运行时优化；NaiveRT 在 6 天内完成 151 轮实验、采用其中 63 轮，将完整投机解码延迟从 12.3 毫秒降至 3.4 毫秒，极速模式最高达到 2,000 tokens/s。AI 还主导推进世界模型 AutoWM，在约 400 小时内完成 15 轮主要实验，并以 77.43 分刷新 WorldArena-1 Track 1 当时的公开成绩。该模型在 PaperBench、MLE-bench-30、PostTrainBench 和 NL2Repo 等研发与编程评测中表现突出，权重及推理代码计划采用 MIT 许可开放。

用途与启示
  • 展示人类设定目标、约束与评价标准，AI 承担编码、实验、监控、分析和验证的 AI 原生递归自我改进范式。
  • 为百万 token 长上下文模型提供 SWA–DSA 混合注意力、分层序列并行与高速推理系统协同优化的实践参考。
  • 说明候选方案筛选、实验验证、失败回滚和系统调优可以智能体化，从而压缩模型研发周期。
  • PaperBench、PostTrainBench 等评测及 AutoWM 案例可用于观察模型承担论文复现、后训练、系统优化和世界模型研发等真实工作的能力。
  • 为建设 AI 原生模型公司与自动化模型研发基础设施提供可观测案例。
