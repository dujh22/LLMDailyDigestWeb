Harness²：双层递归优化智能体执行框架

Google 开源 Harness²，通过任务级与元级双层递归优化智能体执行框架，在不修改模型权重的情况下持续提升任务表现。

★ 3 子主题：脚手架演化 新智元  HarnessEvolve SystemEvolve AgentEvolve

 智能体脚手架演化 递归自我改进 智能体 执行轨迹 经验复用

论文：https://arxiv.org/abs/2610.14224
代码：https://github.com/google-research/harness2
原文：https://mp.weixin.qq.com/s/sgr4lqvQsaqBYAnkdNeMYg
  • Harness² 将系统提示词、护栏、记忆、工具指导、子智能体、技能、脚本和插件定义为八类可编辑的智能体执行组件。
  • 任务级优化采用 PPC（Propose–Probe–Compose）机制，根据执行轨迹提出修改方案，通过实际试运行探测效果，再组合表现最佳的改动。
  • 元级优化会保存成功修改的原因、执行证据和通用经验，用于指导后续未知任务中的框架调整。
  • 在锁定模型权重且不依赖真实标签验证的条件下，单步优化使 GLM-5 与 Gemini 3.5 Flash 在 WorkBuddy-Bench、JobBench 和 LAB 等基准上获得明显提升。
用途与启示
  • 为闭源 API 模型提供无需访问或微调权重的非侵入式能力升级路径。
  • 展示以执行轨迹和实测结果为依据，自动改进提示词、工具、记忆及插件等智能体脚手架的方案。
  • 可将任务内试错经验沉淀为跨任务规则，增强智能体对动态网页、API 和业务流程的适应能力。
  • 为生产级智能体建立“轨迹分析—候选修改—执行验证—经验复用”的闭环演化机制。

RAX：在线探索扩展驱动机器人持续自我改进

RAX 让参数冻结的机器人智能体通过在线探索生成控制程序并积累可复用技能，在五大仿真基准上平均领先既有 SOTA 37.4 个百分点。

 具身智能 自我改进 测试时计算 经验学习 技能演化

论文：https://arxiv.org/abs/2610.22496
代码：https://github.com/robot-agent-exploration/rax
数据集：https://huggingface.co/datasets/robot-agent-exploration/robot-session-logs
原文：https://mp.weixin.qq.com/s/21Pf0S8GnBH33qeGsoo93w

RAX（Robot Agent eXploration）将测试时在线探索引入机器人学习，由通用 Coding Agent 连接感知与控制接口，依据执行反馈持续修改程序。探索成功后，系统把感知、规划和控制逻辑固化为 Code as Policy，并沉淀进技能库，以支持跨任务、跨环境和跨机器人本体复用。在模型参数冻结且不使用遥操作动作示范的条件下，RAX 在 RoboDojo、BEHAVIOR-1K、HumanoidArena、DexJoCo 和 LIBERO-Pro 上平均领先既有 SOTA 37.4 个百分点。真实机器人实验表明，系统可在不到两小时的自主探索中掌握精密插孔、柔性物体操作和长程全身控制等任务，并将空气炸锅任务的执行时间从约 72 分钟缩短至 18 秒。

用途与启示
  • 展示以“扩展在线探索”替代单纯扩展示范数据和策略训练的具身智能发展路径。
  • 为新机器人本体提供接口化适配方案，无需重新采集大量动作示范或微调策略模型。
  • 将高成本探索固化为可检查、可组合、可快速执行的程序化技能，降低后续任务的推理与部署成本。
  • 为具身智能中的持续学习、自我改进和跨本体技能迁移提供可复现实验平台。

提示词工程退潮：核心工作转向智能体 Harness

Riley Goodside认为面向普通用户的“咒语式”提示词工程正逐渐失去必要性，而底层提示、执行框架与系统工程正在成为释放模型能力的关键。

 提示工程 智能体执行框架 智能体脚手架 工具调用 SWE 软件工程

原文：https://mp.weixin.qq.com/s/YoTQ9Yq_mcoF_vIZvGOV2g

Riley Goodside称普通用户已不必依赖复杂模板、角色设定和固定措辞，随着前沿模型理解能力增强，直接描述目标通常即可获得较好结果。文章以Chainguard借助前沿模型和自建执行框架发现PHP高危漏洞为例，指出成果主要依赖沙箱、源码、工具与执行引擎组成的完整 Harness，而非精巧提示词。提示词工程并未完全消失，底层系统提示、小模型适配和应用内提示仍是重要工程工作。其角色正从面向用户的独立职业技能，转变为智能体脚手架、技能封装和系统设计的一部分。

用途与启示
  • 提示优化应从打磨固定措辞，转向明确任务目标、约束条件和验收标准。
  • 构建智能体应用时，应优先投入执行框架、安全沙箱、工具链和反馈闭环。
  • 复杂提示策略仍可作为底层系统能力，但宜由产品或框架封装，而非要求普通用户掌握。
  • PromptEvolve可重点研究提示、脚手架与模型能力之间的协同演化。
