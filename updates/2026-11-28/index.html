CoEvo-RSI：模型与脚手架协同演化

用跨代档案搜索模型与脚手架的最佳配对，避免两者独立升级造成接口错配，让9B模型在垂直任务上超过大型模型。

子主题：协同演化 AI科技评论  AgentEvolve HarnessEvolve

 自演化 智能体 模型与框架协同优化 智能体脚手架 模型训练

论文：https://arxiv.org/abs/2610.25078
原文：https://mp.weixin.qq.com/s/qQY-eKW4Ms4NRGCVA8GEyw
用途

在智能体迭代系统中建立版本档案库，并用 TIMR 与任务得分跨代筛选模型和 Harness 配对，作为低成本协同优化方案。

启示

智能体能力取决于模型与执行框架的匹配关系而非单个组件的新旧程度，保留并重组历史版本可能比线性升级更有效。

📄 详细内容
  • 问题：模型与 Harness 独立迭代后容易出现接口或能力错配，而且任务低分难以归因于模型、流程还是接口。
  • 旧法为何失效：传统协同进化只能继承上一代组合，一旦某代适配失败便可能持续退化；只进化 Harness 会让模型跟不上，只训练模型又受固定框架限制。
  • 方法：CoEvo-RSI 保存历代 Harness、模型检查点、轨迹和得分，以 TIMR 诊断接口错配；元智能体通过“双向历史继承”跨代组合版本，并可用 TIES-Merging 融合检查点，再以成功轨迹进行拒绝采样和全参数 SFT。
  • 实验：迭代10轮、每轮生成8个 Harness 候选，TIMR 始终低于0.22%。Qwen3.5-9B 在 TraceElephant 错误智能体识别上达到70.78%，RBAC-Spider 安全执行准确率达80.85%，陌生 BIRD 数据库上的正确拒绝率达91.26%。
  • 局限与后续：结果集中于故障归因、数据库权限查询和智能家居控制等垂直任务，跨更多任务与更开放环境的泛化能力仍需验证。

RSI 2026：自我进化效果验证

用自主性分级与代表论文对照，回答AI自我修改后如何证明能力真正提升而非过拟合。

★ 3 子主题：递归自我改进 未知  Awesome-RSI HarnessEvolve EvalEvolve GeneralizeEvolve

 递归自我改进 自演化 模型评估 智能体 人工智能可靠性

原文：https://mp.weixin.qq.com/s/Jtp2FP9rBwqnesGAgQdwog
用途

在构建自我改进智能体时，可借鉴L1至L5分级，并用独立留出集、等计算预算和轨迹审计验证每轮修改。

启示

自我修改能力不是RSI成功的充分条件，只有经独立验证且能跨任务延续的收益，才能视为真正的递归改进。

📄 详细内容
  • 问题：RSI已能自动优化提示词、工具、Harness乃至模型权重，但评测涨分是否代表可持续、可泛化且安全的能力提升仍难判断。
  • 旧法为何失效：仅凭固定任务集上的分数接受新版本，会混入任务过拟合、额外计算开销和评估噪声；评估器自身存在偏差时，进化方向也可能被误导。
  • 方法：综述以L1至L5划分自我改进自主性，并梳理十篇代表论文，覆盖Harness搜索、运行时修改、递归元改进、失败类型路由、收益归因及评估器验证。
  • 实验：Meta-Harness将在线分类成绩提高7.7个百分点且仅用四分之一上下文Token；Exo降低35%至61%的模型调用成本。另一项归因研究发现平均54%的进化收益来自过拟合、14%来自额外计算，而仅用16个样本筛选会高估13至20个百分点。
  • 局限与后续：跨任务泛化、原有能力保持、评估器可信度及生产环境中的安全边界仍是RSI走向真实应用的核心挑战。

AutoSFT：多角色自动研究微调数据

用执行、分析和合成智能体扩展微调数据动作，解决单智能体只会调整样本比例的问题，IFEval 最高达81.58。

 智能体 数据工程 模型训练 数据合成 多智能体系统

论文：https://arxiv.org/abs/2610.22194
原文：https://mp.weixin.qq.com/s/otwODaP4i6WavccJEt4XnQ?scene=1&click_id=81121034
用途

在自动化SFT数据优化系统中借鉴其角色分工与六类数据动作，让智能体依据失败案例迭代筛选、修复、重新监督和合成训练样本。

启示

自动化数据优化的关键瓶颈不是单次动作能力，而是能否扩大可执行的数据动作空间，并隔离执行噪声以保留可归因的研究反馈。

📄 详细内容
  • 问题：自动化监督微调中的单智能体往往只调整类别采样比例，难以修复坏样本、重新监督或生成缺失能力的数据。
  • 旧法为何失效：训练执行日志占满决策上下文，且单一研究视角导致动作空间坍缩；基线连续33轮只使用混合比例调整，未修改或新增样本。
  • 方法：AutoSFT 每轮从同一基础模型重新训练，将研究回路拆为执行、分析、合成三个子智能体，并由元智能体选择数据动作；分析覆盖数据质量、失败案例、学习动态与历史尝试，合成样本还需经过规则、语义和重复度验证。
  • 实验：执行分工将上下文压缩次数从10次降至5次；分析配置在IFEval上30轮达到67.10，修复与重新监督占动作的55%；加入合成后IFEval由78.15升至81.58、IFBench由49.02升至51.95，代码任务第6轮达到65.8%。
  • 局限与后续：实验固定训练器、模型和预算，主要覆盖IFEval、IFBench与MBPP+；部分能力增加样本后仍为0分，多智能体还带来额外运行时间和API成本。

Solve Vision with Code：程序合成式视觉推理

让编码智能体编程渲染答案视频，比直接生成像素的视频模型更可靠，最高得分0.923。

子主题：视觉推理 Hugging Face Papers  ReasoningEvolve

 视觉推理 人工智能辅助编程 多模态 模型评估 推理

论文：https://arxiv.org/abs/2611.34813
用途

在可程序化求解的视觉任务中，可借鉴“智能体编程渲染视频”机制作为视频生成模型的推理基线或可审计替代方案。

启示

视觉媒介中的推理不必依赖原生像素生成，显式程序可将视觉理解转化为更可靠、可检查且可迁移的符号计算。

📄 详细内容
  • 问题：检验视频生成是否真是更可靠的视觉推理方式，并在相同输入、输出要求和评估器下与符号化程序合成进行公平比较。
  • 旧法为何失效：视频模型通过像素去噪直接生成推理过程，结果难以显式检查；此前也缺少与程序化解法条件一致的对照实验。
  • 方法：编码智能体仅根据首帧和自然语言提示编写程序、渲染答案视频，再由不做修改的规则评估器评分；同时区分从图像恢复可迁移方案的描绘式程序与依赖硬编码值的命题式程序。
  • 实验：在含500个样本、覆盖五类认知任务的VBVR-Pro-Bench上，Codex、Claude Code和Gemini CLI分别取得0.923、0.894和0.893，均比最强视频模型高逾0.22；23个可运行开放权重模型中，GLM-5最高为0.572。
  • 局限与后续：结论适用于可由首帧和提示计算答案、且具有符号真值的任务；开放权重编码模型整体仍明显落后于闭源编码智能体。

AutoRL：多智能体自治强化学习

 强化学习 模型训练 多智能体系统 智能体 执行恢复

论文：https://arxiv.org/abs/2611.17790
原文：https://mp.weixin.qq.com/s/7WvZQ4uBttw3HkFvoa8MrQ?scene=1&click_id=1179981389
用途

在长周期大模型强化学习系统中，可借鉴其角色分工、低成本提案验证及热更新与检查点恢复机制，实现在线训练运维和配方优化。

启示

训练中的平台期、异常和失败并非单纯运维噪声，而是可驱动配方发现的研究证据，关键是让专门化监督与可回滚干预形成闭环。

📄 详细内容
  • 问题：强化学习训练状态持续变化，还会遭遇奖励缺陷、性能平台期、数值异常和分布式运行故障，需要在训练过程中及时诊断与干预。

用途

在开发或选型深度研究智能体时，可将DRBench Pro作为基准，分别诊断报告的方向覆盖广度和知识链探索深度。

启示

研究报告的知识质量不能只看整体写作表现，必须保留知识关系结构，才能区分“覆盖得广”和“挖掘得深”两种独立能力。
