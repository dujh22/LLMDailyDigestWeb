程序图 PG：连接工具、技能与记忆的自进化智能体脚手架

谷歌、佐治亚理工学院与北京大学提出程序图 PG，通过可验证的离线演化持续优化工具、技能、记忆和任务状态之间的程序关系，无需更新模型权重即可提升智能体执行能力。

子主题：脚手架演化 新智元  HarnessEvolve

 智能体脚手架演化 智能体 自演化 智能体记忆 长程任务

论文：https://arxiv.org/abs/2609.09153
原文：https://mp.weixin.qq.com/s/l4W93-7aMsL4AlwuuwZCNw

程序图（Procedural Graphs，PG）以带条件、执行建议和避坑信息的有向边，连接工具调用、技能步骤、内部推理、记忆操作与任务状态，将“何时做、按何顺序做”显式表示为程序性知识。在线执行时，系统定位智能体当前步骤并读取两跳内的局部子图，再结合任务与近期轨迹生成指导，避免整图上下文带来的无关信息和高 Token 开销。离线阶段，系统分析高低分轨迹并提出增删节点、调整连接或改写指导的候选修改，只有通过结构检查且验证分数不下降的版本才会被采纳。在 MultiChallenge、BFCL v3、ALFWorld 和 EnterpriseArena 等任务上，PG改善了多轮指令遵循、工具调用与长期决策表现；其中 ALFWorld 局部子图指导相较整图指导将平均 Token 消耗降低约 70.9%。

用途与启示
  • 为智能体 harness 提供可解释、可编辑且无需更新模型权重的程序性记忆层。
  • 将工具、技能和长期记忆的调用条件与先后关系显式化，减少过度执行、遗漏检查和错误终止。
  • 通过独立验证集筛选图结构修改，为智能体脚手架的安全迭代提供验证棘轮机制。
  • 局部子图检索可在保留步骤依赖关系的同时降低上下文成本，适合长程任务和复杂工具链。

简单讲讲 Agent 的工作原理

文章从 Harness 的上下文自动化编排出发，解释 Agent 如何通过模型判断、工具执行、反馈循环、历史压缩与多智能体交接持续完成任务。

子主题：智能体框架 Agent train 

 智能体 人工智能框架 智能体工具 长上下文 多智能体协作

原文：https://mp.weixin.qq.com/s/EQMPyo5FVCFvy0mndcBkMQ

Agent 的核心运行方式是由 Harness 组装指令、对话、任务资料和工具结果，使模型基于当前上下文决定直接回答或发起工具调用。工具执行结果会进入下一轮请求，形成“模型判断—工具执行—反馈修正”的循环，让代码修改、命令运行和结果校验能够连续推进。面对长程任务，系统可通过限制工具输出、压缩历史、保存文件和重读进度记录来控制上下文容量，并采用渐进加载方式按需引入 Skill、MCP 与插件能力。多 Agent 协作还需明确任务拆分、上下文继承和结构化交接，同时维护运行中消息的顺序以及工具调用与返回结果的配对关系。

用途与启示
  • 帮助理解 Agent 产品的连贯体验并非来自单次模型调用，而是来自 Harness 对上下文、工具和反馈的持续编排。
  • 为设计长程 Agent 提供实践思路，包括按需加载技能、压缩历史、持久化进度以及必要时重读原始资料。
  • 提醒多智能体系统不仅要拆分任务，还要定义交接内容、证据格式和校验机制，避免关键依据在汇总时丢失。
  • 强调文件存储、会话记录与模型当前上下文是不同层次，信息被保存并不等于会被后续请求自动读取和遵守。

  • 提醒将线上业务指标作为最终标准，持续修正 Benchmark 和奖励信号，降低错误目标被模型放大的风险。

IntBMoE：块级条件驱动的全参与式混合专家模型

IntBMoE通过密集专家组合与稀疏块执行，将专家参与度、计算开销和参数实体化成本解耦，并已在高德生成式推荐系统中实现线上收益。

子主题：模型架构创新 Hugging Face Papers 

 混合专家模型 模型开发 系统优化 人工智能应用

论文：https://arxiv.org/abs/2609.21346
代码：https://github.com/AMAP-ML/DreamX-Rec/

IntBMoE区分单个词元的专家参与度、实际执行专家数和需构建存储的专家参数集数量，并针对三者难以独立控制的问题提出块级条件化架构。模型利用小型可学习码本定义固定数量的块，由轻量级超网络在每个内部层融合池中的全部专家基底，从而实现全专家参与。路由器仅将词元发送到少量块，使执行保持稀疏，而固定码本则限制参数实体化成本；双路径残差门控（DPRG）进一步通过乘法门控耦合两条独立组合路径。该方法在图像分类、语言建模和序列推荐中优于代表性MoE基线，并在高德生成式推荐系统的数亿用户场景中满足60毫秒延迟预算，线上A/B测试取得2.4%的相对UVCTR提升。

用途与启示
  • 为MoE架构设计提供参与度、执行量和参数实体化量三个相互独立的优化维度。
  • 适用于需要扩大模型容量、同时严格约束推理延迟与内存成本的线上系统。
  • 展示了超网络专家组合、稀疏块路由和固定码本结合的工程化方案。
  • 其跨视觉、语言和推荐任务的结果表明，该架构具备较好的跨领域泛化潜力。

RSI并非单一时刻，而是从模型写代码、监控实验和提出新实验，逐步走向自主调整数据、架构与权重的连续过程，其终局可能是不再需要人类介入的自我改进闭环。当前可行路径通常仍依赖外部辅助模型、Harness、应用环境与反馈信号，模型还需具备识别自身不足、设定改进目标并持续纠偏的能力。RSI评估不应只衡量模型学会了什么，还应考察其如何学习、能否在真实工作环境中产生价值，以及性能提升是否可复现。验证被视为持续演进的核心瓶颈：模型既要避免自出题、自解题造成的局部最优，也要处理硬件和运行环境差异带来的测量偏差。产业层面，大模型厂商更适合探索通用模型的自我迭代，创业公司的机会则集中在专业知识、数据、环境、验证体系及Harness演化。
