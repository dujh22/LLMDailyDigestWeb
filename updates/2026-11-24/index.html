MetaRSI/RSI²：双轴元递归自改进

用可演化的双轴调度统一数据、脚手架与模型改进，解决RSI只改权重且规则固定的问题。

★ 3 子主题：递归自我改进 未知  Awesome-RSI SystemEvolve

 递归自我改进 自演化 系统优化 执行验证 模型训练

用途

在AI能力迭代平台中借鉴其算子隔离、工件新鲜度合约和双轴调度，编排可验证的数据、脚手架与模型升级流程。

启示

递归自我改进能否持续取决于不可改写的验证边界和对过期自我认知的及时刷新，而非单纯扩大模型能力。

📄 详细内容
  • 问题：传统递归自我改进主要优化模型权重，难以联合演化数据、评估环境和调度规则，也缺少面向生产流水线的统一验证与审计机制。
  • 旧法为何失效：单对象更新无法处理组件间依赖；系统能力改变后，旧数据和旧工件会立即过期，写入范围重叠还可能破坏改进结果的可信性。
  • 方法：以统一循环内核约束Data-RSI、Harness-RSI和Model-RSI三个写入面互斥的算子，分别负责经验放大、零训练能力补丁和能力内化；工件必须生成于最近一次能力变更之后，6种跨算子迁移中仅允许5种。通过水平编排轴安排算子顺序、垂直优化轴改进算子内部策略，并以RSI²调度层和MetaRSI²元调度层继续优化预算、停止条件及调度规则。

MetaRSI/RSI²：面向RSI的元递归自改进框架CosmosMind Lab联合清华、北大、斯坦福、麻省理工、帝国理工、港大等推出了一个颠覆式技术框架：MetaRSI-v1，它把递归自改进(RSI)从单一的“改模型权重”，升级成了一套覆盖整个RSI领域、面向AI生产流水线的元递归框架。 普通的递归自改进AI(RSI)，目标只是让模型优化自身能力。而MetaRSI更进一步：它不仅能修改模型参数，还能修改数据集、评估环境，甚至优化这套自我迭代的调度规则本身 —— 也就是演化规则自己也能演化。 简单说：它不止是「AI改进AI」，它改进「AI改进AI的方式」本身。 MetaRSI-v1可以理解是一套覆盖了整个RSI领域的架构语言：包括一个内核、两条轴、三个算子、嵌套元RSI层，以及五大定律。 一个内核代表了统一循环内核范式，所有三类算子共享同一套循环内核契约，保证不同算子运行、验证、审计标准统一。 三大算子，每个算子仅能修改对应一个组件，写入面严格不重叠。Data-RSI：经验放大器与能力边界标记器；Harness-RSI：零训练成本的快速能力补丁；Model-RSI：能力内化器。 算子消费的所有工件，必须生成于最近一次能力变更之后。Harness-RSI与Model-RSI属于能力变更算子，执行后系统行为改变，旧数据立即失效。Data-RSI不改变系统行为，不属于能力变更步。三个算子两两组合共6种跨算子迁移，5个合法，1个被禁止。 水平轴/编排轴：决定算子执行顺序，生成合法的算子序列，扩展改进流水线；垂直轴/优化轴：不调用算子，而是在合约范围内修改单个算子的内部提案策略，优化算子的诊断逻辑、优先级、输出格式。 MetaRSI真正的“Meta”(元)，体现在三层嵌套的改进层级上。 内核层/基础循环层：改系统本身，就是上面三个算子干活，每跑一轮循环，改一次AI系统。 RSI²双轴调度层：改“改系统的顺序和方法”，不直接改AI，而是决定下一步先调用哪个算子、按什么顺序组合。同时，还能优化每个算子自己的工作方法，比如复盘组该怎么定位问题，流程组该优先改什么。 MetaRSI²元调度层：改“调度的规则”，每跑完一整个改进周期，元代理会回头看：之前的调度策略好不好、预算分配对不对、什么时候该停。然后更新调度规则，下一轮用更优的策略来跑。 五条可证伪的递归自改进定律：自改进的边界，是校验的边界，不是能力的边界；自我认知会过期，重新描述是速率瓶颈；能力与载体无关，成本与载体强相关；信任由不可改写的部分度量；循环不创造能力，所有增益均为外部导入 。

用途

在设计自改进智能体或训练闭环时，用该双循环框架拆分提出、评估与学习模块，并审计改进是否持久、是否反馈到改进机制本身。

启示

递归自我改进的关键不是重复优化系统，而是让改进算子进入反馈回路；这会解除固定上限，却也把持续进步转化为评估可靠性问题。

📄 详细内容
  • 问题：区分只修订当前产物、把经验写入能力，以及连改进流程本身也持续更新的三种改进强度，并形式化递归自我改进的成立条件。
  • 旧法为何失效：固定改进算子的迭代轨迹由起点和算子完全决定；在收缩假设下，能力趋向固定不动点，单轮收益呈几何衰减。
  • 方法：用“系统状态—能力度量—改进算子”统一建模，再引入元改进算子与实验反馈形成双循环；并将每轮改进拆为提出者、评估者和学习者，映射到 Self-Refine、DGM、STaR、Self-Rewarding、Absolute Zero 与 AlphaEvolve。
  • 实验：文章以代表系统验证框架，其中 DGM 通过版本档案和多路径探索，在约80代内将 SWE-bench 从20.0%提升至50.0%，Polyglot 从14.2%提升至30.7%。
  • 局限与后续：改进算子发生变化不等于变得更好，算子变好也不保证单轮收益递增；反馈噪声和评估误差仍可能筛错候选并导致能力退化。

HarnessDev：自建执行框架评测

用先构建再运行执行框架的两阶段测试，评估模型管理循环、调用工具和恢复错误的能力。

 智能体评估 智能体脚手架 工具调用 执行恢复 模型评估

用途

在智能体开发与模型选型中，可将其作为基线，评估不同模型自主搭建和优化 Agent Harness 的能力。

启示

智能体能力不仅取决于模型本身，还取决于模型能否设计出有效的外部执行控制系统，因此评测应同时覆盖脚手架构建与实际运行。

📄 详细内容
  • 问题：衡量模型能否自行构建和优化 Agent Harness，而不只是在固定执行框架中完成任务。
  • 旧法为何失效：只比较模型权重或在预设 Harness 上测试，难以反映模型管理执行循环、工具调用与错误恢复的能力。
  • 方法：设置创建与执行两阶段；模型先从故意设计得较弱的框架出发，按任务规范开发完整执行系统，再在自己生成的系统上运行并接受任务表现评估。
📝 原始笔记（逐字保留）
🤖 HarnessDev 字节提出的 HarnessDev，是用于衡量模型构建和优化 Agent Harness 框架能力的全新基准测试；研究认为，Agent 的性能不再依赖于模型权重，更取决于管理执行循环，工具调用和错误恢复的外部 Harness 框架； 其核心评估过程分为两个阶段： 创建阶段：从一个故意被设计的很弱的框架出发，据任务规范开发出一套完整的执行系统； 执行阶段：模型在自己生成的执行系统上进行运行，并评估任务表现；

Declarative Attention：自主声明注意力范围

让模型在思维链中自主声明注意力范围，避免逐词扫描全部上下文，降低显存占用与推理延迟。

★ 3 子主题：缓存优化 未知  SystemEvolve CacheEvolve

 推理加速 缓存优化 系统优化 成本优化 长上下文

用途

在长上下文生成系统中借鉴三档声明式注意力机制，让模型按当前推理需求动态缩小 KV 缓存读取范围。

启示

思维链不仅能表达推理过程，还可充当计算资源的控制接口，让模型主动决定每一步需要调用多少上下文。

📄 详细内容
  • 问题：生成每个词元时都需读取完整上下文的 KV 缓存，即使真正相关的内容很少，长上下文推理仍面临较高显存和延迟开销。
  • 旧法为何失效：已有方法多依赖外部打分器筛选保留词元，但解码时的时间复杂度仍为 O(N)。
  • 方法：提出声明式注意力，让模型在思维链中自主选择全局、聚焦或本地三种注意力模式，动态限定当前所需的关注范围。
  • 实验：在 Qwen 和 Gamma 模型上基本维持准确率，同时显著减少显存开销与推理延迟。
📝 原始笔记（逐字保留）
🤖 Declarative Attention 在生成最终回答时，模型每生成一个 Token 都需要读取全部上下文的 KV 缓存，即使它只需要关注其中很少的一部分词；现有方案大多采用外部打分的方式来决定保留哪些 Token，来降低资源开销，但解码过程的时间复杂度仍为 O(N)； ⭐️ DeepMind 提出一种「声明式注意力」的方案，模型能够在思维链（CoT）中自主选择当前需要的注意力作用范围，分为全局，聚焦，本地三种模式；在基本维持高准确的同时，显著减少了 Qwen 和 Gamma 模型的显存开销与推理延迟；
