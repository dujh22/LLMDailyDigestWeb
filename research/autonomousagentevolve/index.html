AutonomousAgentEvolve

研究方向：自主 Agent 自进化——让 Agent 从"用户发一句、它答一句"的被动会话，走向跨会话持续运行、自主决定何时醒来与何时汇报的常驻（always-on）形态，并在无人监督的长程运行中依靠持久记忆、自设定时器与权限边界持续积累经验、自我改进。

研究范畴

自主 Agent 自进化（autonomous / always-on agent self-evolution）关注的不是单次任务里的推理链，而是 Agent 在"睡眠—唤醒—工作—沉淀"的无限循环中如何保持连续性并越跑越好。Anthropic 在《Building always-on agents》中给出了一个可工程化的参照框架：所谓"常驻"只是用户体验，Agent 实际上大部分时间在休眠，每次被事件唤醒执行一段 run，run 运行在承载消息与工具调用记录的 session 中；包裹核心 Agent 循环的外部架构由五个原语组成——事件收件箱（webhook、定时任务、后台作业统一写入持久事件表，单 worker 消费、去重、批处理，防止并发 run 与事件丢失）、定时器（Agent 给自己设的 follow-up 与周期性 schedule，由调度器轮询后投递回收件箱）、记忆（用户指令、用户画像、已发消息、任务进度分文件持久存储，只加载索引，并可通过 “dreaming” 回顾历史会话整理记忆）、权限（凭据代理注入、auto mode 分类器拦截高风险动作、deferred tool call 挂起等待用户批准）与发件箱（分离的出站消息表与 dispatcher，控制汇报节奏，“先安静、再逐步赢得用户注意力”）。本方向把这一架构视为自进化的载体：记忆与 dreaming 构成跨 run 的经验积累通道，定时器让 Agent 自主规划后续行动，权限与发件箱则是自主性的安全与人机交互边界。与 AgentEvolve 关注单个 Agent 的推理时反思与技能积累、HarnessEvolve 关注脚手架本身的演化、MemoryEvolve 关注记忆机制不同，AutonomousAgentEvolve 关心的是"长期无人值守运行"这一系统形态下的整体闭环：事件驱动的唤醒、跨 session 的状态延续、主动性与打扰之间的平衡，以及以"每个已解决任务的成本"而非单 token 价格衡量的长程经济性——Anthropic 的成本文档显示，在 SWE-bench Pro 子集上从 Opus 5 升级到 Opus 5.5，解题率基本持平（91.9% → 92.8%），每个已解决任务的成本下降 78%（按 Opus 5 价格折算约 69%），而典型负载下的降幅为 40%，长程任务正是模型进步最受益的场景。

研究挑战

  • 跨 run 连续性：会话被压缩或重开都会丢失细节，哪些信息必须写入记忆、哪些只存指针（“只记无法再查到的东西”）仍缺乏系统性方法。
  • 记忆的整理与进化：dreaming 式离线回顾如何识别过时条目、提炼只在多次运行中才显现的模式，又不把错误经验固化。
  • 主动性与打扰的平衡：发多了是噪声、发少了漏掉关键信息，需要专门 eval 来校准汇报频率与时机。
  • 无人值守下的权限与安全：run 持有用户访问权限且默认无人监督，凭据隔离、高风险动作分类拦截、何时必须挂起等待人类批准都是开放问题；事件内容中的提示注入需在 run 内深度校验。
  • 并发与可靠性：多事件同时到达、worker 中途崩溃、run 中途插入新事件（推迟 / 合并 / 中断重启）等分布式系统问题与 Agent 语义交织。
  • 长程经济性评测：上下文开销在每个 run 中重复支付，需要以每个已完成任务的成本、尾部最难任务的成本来评估，而非每 token 价格。
  • 自主改进的可追溯性：Agent 自设定时器、自写记忆、自调整行为，如何让每一次能力或行为变化可审计、可回滚。
